# 04 - 术语表

> AI Agent 领域的 **100 个常用术语**。按主题分类，每个术语给出**定义、相关概念、参考文档**。

---

## 一、基础概念（15 个）

### 1. LLM (Large Language Model)

- **定义**：大语言模型，基于 Transformer 的大规模预训练语言模型。
- **代表**：GPT-4、Claude 3、Gemini、Llama 3。
- **相关**：Transformer、Pre-training、Fine-tuning。

### 2. Prompt

- **定义**：用户输入给 LLM 的文本指令。
- **组成**：系统提示词 + 用户输入 + 上下文。
- **相关**：Prompt Engineering、Few-shot、Chain-of-Thought。

### 3. Token

- **定义**：LLM 处理文本的最小单位（通常是 subword）。
- **注意**：英文 1 token ≈ 0.75 单词；中文 1 token ≈ 1-2 字。
- **成本**：LLM API 按 token 计费。

### 4. Context Window

- **定义**：LLM 单次调用能处理的最大 token 数。
- **代表**：GPT-4 Turbo 128K、Claude 3 200K、Gemini 1.5 1M。
- **限制**：超过窗口的内容会被截断。

### 5. Embedding

- **定义**：把文本转为高维向量表示（用于语义检索）。
- **模型**：OpenAI text-embedding-3、Cohere embed、BGE。
- **用途**：RAG、相似度计算、聚类。

### 6. Fine-tuning

- **定义**：在预训练模型上，用特定数据集继续训练以适配特定任务。
- **对比**：Prompt Engineering 不改模型权重，Fine-tuning 改。
- **成本**：高（数据准备 + 训练 + 部署）。

### 7. RLHF (Reinforcement Learning from Human Feedback)

- **定义**：基于人类反馈的强化学习，让 LLM 行为对齐人类偏好。
- **代表**：InstructGPT、Claude 的 Constitutional AI。
- **相关**：RLAIF、DPO、PPO。

### 8. Hallucination

- **定义**：LLM 生成看似真实但不正确的内容。
- **类型**：事实幻觉、引用幻觉、逻辑幻觉。
- **缓解**：RAG、答案验证、人工审核。

### 9. Temperature

- **定义**：控制 LLM 输出随机性的参数（0-2）。
- **高温度**：更有创造性、多样化。
- **低温度**：更确定、稳定。

### 10. Pre-training

- **定义**：在大规模无标注数据上训练基础模型。
- **成本**：极高（千万美元级）。
- **代表**：GPT-4、Claude 3、Llama 3 405B。

### 11. Inference

- **定义**：用训练好的模型做预测（生成文本）。
- **成本**：比训练低，但仍可观。
- **优化**：vLLM、TGI、量化（GGUF、AWQ）。

### 12. Quantization

- **定义**：把模型权重从高精度（FP32）转为低精度（INT8、INT4）。
- **目的**：减少显存占用、加速推理。
- **代价**：可能略微降低质量。

### 13. Transformer

- **定义**：基于 Self-Attention 的神经网络架构，2017 年提出。
- **地位**：现代 LLM 的基础架构。
- **代表论文**：Attention Is All You Need。

### 14. Attention

- **定义**：让模型关注输入中相关部分的机制。
- **变体**：Self-Attention、Multi-Head Attention、Flash Attention。
- **关键**：Transformer 的核心创新。

### 15. Mixture of Experts (MoE)

- **定义**：把模型分成多个"专家"子网络，每次只激活部分。
- **代表**：Mixtral、GPT-4（推测）。
- **优势**：大参数、低推理成本。

## 二、Agent 概念（15 个）

### 16. Agent

- **定义**：能感知环境、决策、执行动作的智能体。
- **核心**：自主性、目标导向、工具使用、长期记忆。
- **对比**：传统 AI 系统是被动的，Agent 是主动的。

### 17. Tool-use

- **定义**：让 LLM 调用外部工具（搜索、计算、API）。
- **机制**：Function Calling、MCP。
- **代表论文**：Toolformer。

### 18. Function Calling

- **定义**：LLM 输出结构化的函数调用指令，由外部系统执行。
- **代表**：OpenAI Function Calling、Anthropic Tool Use。
- **格式**：JSON Schema 描述函数签名。

### 19. MCP (Model Context Protocol)

- **定义**：Anthropic 推动的 Agent 工具协议。
- **目的**：标准化 AI 模型与外部工具的交互。
- **类似**：USB-C for AI。

### 20. ReAct

- **定义**：Reasoning + Acting，让 LLM 推理和行动交替。
- **模式**：Thought → Action → Observation → ...
- **应用**：研究型 Agent。

### 21. Chain-of-Thought (CoT)

- **定义**：让 LLM 逐步推理，提升复杂任务表现。
- **变体**：Self-Consistency、Tree of Thoughts。
- **应用**：数学、逻辑推理。

### 22. Planning

- **定义**：Agent 自主规划任务步骤的能力。
- **方法**：Plan-and-Execute、HuggingGPT。
- **关键**：可执行性、纠错能力。

### 23. Memory

- **定义**：Agent 的持久化记忆系统。
- **分类**：短期（上下文）、长期（向量数据库）、永久（知识库）。
- **代表**：Mem0、Letta、MemoryBank。

### 24. Reflection

- **定义**：Agent 自我审视输出并改进的能力。
- **模式**：生成 → 批评 → 改进。
- **应用**：内容生成、代码生成。

### 25. Self-Consistency

- **定义**：多次采样 + 投票，提升稳定性。
- **应用**：高准确率任务（数学、推理）。
- **代价**：成本 × N。

### 26. Tree of Thoughts (ToT)

- **定义**：把推理过程建模为搜索树。
- **对比 CoT**：CoT 是线性，ToT 是树状探索。
- **应用**：复杂规划、博弈。

### 27. Routing

- **定义**：把不同请求分发到不同处理路径。
- **场景**：多领域客服、多类型任务。
- **实现**：LLM 分类 + 路由表。

### 28. HITL (Human-in-the-Loop)

- **定义**：人工介入 AI 决策的关键节点。
- **场景**：高风险操作（删除、转账、对外）。
- **关键**：SLA + 升级机制。

### 29. SWE-bench

- **定义**：评估 LLM 软件工程能力的基准。
- **任务**：真实 GitHub issue 的修复。
- **代表 Agent**：Devin。

### 30. Agentic Workflow

- **定义**：以 Agent 为核心的工作流设计模式。
- **对比**：传统 workflow 是确定的，Agentic workflow 是自主的。
- **代表**：OpenClaw、LangGraph、AutoGen。

## 三、RAG 与数据（15 个）

### 31. RAG (Retrieval-Augmented Generation)

- **定义**：检索外部知识 + LLM 生成回答。
- **优势**：减少幻觉、知识更新、可追溯。
- **相关**：Vector DB、Embedding、Re-ranking。

### 32. Vector Database

- **定义**：专门存储和检索高维向量的数据库。
- **代表**：Pinecone、Weaviate、Milvus、Chroma。
- **用途**：RAG、相似度搜索、聚类。

### 33. Semantic Search

- **定义**：基于语义（而非关键词）的搜索。
- **方法**：Embedding + 向量相似度（Cosine / Euclidean）。
- **对比**：传统关键词搜索（BM25、TF-IDF）。

### 34. Chunking

- **定义**：把长文档切分为小段（chunk），用于 RAG。
- **策略**：按 token 数、按段落、按语义。
- **最佳实践**：chunk size 500-1000 tokens，overlap 10-20%。

### 35. Re-ranking

- **定义**：对 RAG 检索结果重新排序，提升精度。
- **方法**：Cross-Encoder 模型、BGE Reranker、Cohere Rerank。
- **位置**：检索后、生成前。

### 36. Hybrid Search

- **定义**：结合语义搜索 + 关键词搜索。
- **优势**：兼顾语义理解和精确匹配。
- **代表**：BM25 + Embedding。

### 37. Knowledge Graph

- **定义**：用图结构表示实体和关系。
- **与 RAG**：互补（RAG 检索段落，KG 检索关系）。
- **代表**：Neo4j、ArangoDB。

### 38. Embedding Model

- **定义**：把文本转为向量的模型。
- **代表**：OpenAI text-embedding-3、BGE-large、Cohere embed-v3。
- **维度**：768、1024、1536、3072 维。

### 39. Few-shot Learning

- **定义**：给 LLM 几个示例，让它学会新任务。
- **对比 Fine-tuning**：不修改模型权重。
- **最佳实践**：3-5 个示例效果最好。

### 40. Zero-shot Learning

- **定义**：不给示例，让 LLM 直接完成任务。
- **适用**：通用任务、模型已经见过类似任务。
- **效果**：通常不如 Few-shot。

### 41. Cosine Similarity

- **定义**：两个向量的余弦相似度（-1 到 1）。
- **用途**：Embedding 检索。
- **特点**：忽略向量长度，只看方向。

### 42. Top-K

- **定义**：检索返回相似度最高的 K 个结果。
- **典型值**：3-10。
- **调优**：太小 → 漏召回；太大 → 引入噪声。

### 43. Context Stuffing

- **定义**：把所有检索结果塞进 LLM 上下文。
- **风险**：可能超出 context window。
- **解决**：先 re-rank，再选 Top-K。

### 44. Query Rewriting

- **定义**：把用户问题改写为更适配检索的形式。
- **方法**：用 LLM 改写、添加同义词、扩展缩写。
- **作用**：提升 RAG 召回率。

### 45. Evaluation Set

- **定义**：用于评估 RAG / Agent 表现的测试集。
- **组成**：输入 + 期望输出。
- **关键**：要覆盖真实场景分布。

## 四、Multi-Agent（10 个）

### 46. Multi-Agent System

- **定义**：多个 Agent 协同完成任务的系统。
- **范式**：Orchestrator + Specialist、Peer-to-Peer。
- **代表**：OpenClaw、MetaGPT、CrewAI。

### 47. Orchestrator

- **定义**：调度其他 Agent 的"指挥官"Agent。
- **职责**：任务分解、依赖分析、调度决策、状态管理。
- **代表**：OpenClaw 的 Orchestrator Agent。

### 48. Specialist Agent

- **定义**：在特定领域做深的 Agent。
- **例子**：产品 Agent、UI Designer Agent、Coder Agent。
- **设计**：每个有独立 SOUL.md 和工具集。

### 49. Reviewer Agent

- **定义**：专门做质量审核的 Agent。
- **职责**：检查其他 Agent 输出是否符合契约。
- **价值**：避免"自评自夸"。

### 50. SOUL.md

- **定义**：Agent 的"心智"配置文件。
- **内容**：Identity、Capabilities、Rules、Tools、Constraints。
- **作用**：定义 Agent 的行为边界。

### 51. Product / UI / Architecture / Coder / QA / DevOps Agent

- **定义**：6 类标准 Agent 角色（软件工程）。
- **来源**：参考真实软件工程团队分工。
- **应用**：OpenClaw 默认配置。

### 52. Wave Execution

- **定义**：按依赖关系分波次执行任务。
- **算法**：拓扑排序 + 入度递减。
- **目的**：最大化并行度。

### 53. Task DAG

- **定义**：任务依赖图，有向无环图。
- **节点**：任务。
- **边**：依赖关系。

### 54. Shared Storage / Shared Workspace

- **定义**：多个 Agent 共享的文件系统（shared/）。
- **通信方式**：写产物 → 读产物。
- **对比**：避免直接对话通信。

### 55. Artifact-Driven Communication

- **定义**：通过结构化产物（文档、文件）通信。
- **对比**：Chat-based 直接对话。
- **优势**：低开销、易调试、可重放。

## 五、工程化（15 个）

### 56. Prompt Engineering

- **定义**：设计、优化 LLM 输入提示词的工程实践。
- **核心**：清晰、具体、约束、Few-shot。
- **相关**：CoT、Self-Consistency、Constitutional AI。

### 57. Prompt Versioning

- **定义**：用 Git 管理 prompt 版本。
- **原因**：prompt 是"代码"，需要版本化。
- **工具**：PromptLayer、Agenta、Humanloop。

### 58. A/B Testing Prompt

- **定义**：对比两个 prompt 的实际效果。
- **方法**：50% 用户用 A，50% 用 B，对比关键指标。
- **关键**：样本量足够、指标定义清晰。

### 59. Evaluation Metrics

- **定义**：评估 LLM 输出的指标。
- **类型**：自动（pass rate、accuracy）、人工（NPS、Likert）。
- **挑战**：开放式任务难自动评估。

### 60. Quality Gate

- **定义**：可机器验证的质量检查。
- **示例**：PRD 字数 > 500、API Spec 是有效 OpenAPI 3.0。
- **关键**：可验证、可量化、分层。

### 61. Self-Healing

- **定义**：Agent 自动检测并修复错误的机制。
- **步骤**：错误分类 → 重试策略 → 升级机制。
- **目标**：7×24 稳定运行。

### 62. Circuit Breaker

- **定义**：当错误率过高时暂时停止服务，防止雪崩。
- **状态**：Closed（正常）/ Open（熔断）/ Half-Open（探测）。
- **应用**：保护后端服务。

### 63. Rate Limiting

- **定义**：限制 API 调用频率。
- **实现**：Semaphore、Token Bucket、Sliding Window。
- **应用**：防止 QPS 超限。

### 64. Idempotency

- **定义**：同一操作执行多次结果相同。
- **实现**：请求 ID + 结果缓存。
- **应用**：Webhook 重试、分布式系统。

### 65. Tracing (Distributed Tracing)

- **定义**：跟踪请求在分布式系统中的完整路径。
- **工具**：OpenTelemetry + Jaeger / Tempo。
- **价值**：定位慢请求、错误根因。

### 66. Metrics (Prometheus)

- **定义**：聚合的时序数据指标。
- **类型**：Counter（递增）、Gauge（瞬时）、Histogram（分布）。
- **应用**：成功率、延迟、Token 消耗。

### 67. Logging (Structured Logging)

- **定义**：结构化日志（JSON 格式）。
- **库**：Python structlog、Go zap、JS winston。
- **价值**：可搜索、可聚合。

### 68. Alerting

- **定义**：基于指标的告警通知。
- **分级**：Warning（通知）、Critical（电话）。
- **反模式**：告警疲劳（太多低质量告警）。

### 69. SLO (Service Level Objective)

- **定义**：服务等级目标（如 99.9% 可用性）。
- **应用**：定义"成功"的量化标准。
- **价值**：避免过度承诺。

### 70. Error Budget

- **定义**：允许的失败率（如 0.1%）。
- **应用**：在错误预算内可以快速迭代，超过则停止。

## 六、安全与合规（10 个）

### 71. Prompt Injection

- **定义**：用户输入中嵌入恶意指令，试图让 LLM 越权。
- **类型**：直接注入、间接注入。
- **防御**：输入清洗、输出过滤、角色约束。

### 72. Jailbreak

- **定义**：绕过 LLM 安全限制（如 DAN 攻击）。
- **防御**：Constitutional AI、RLHF、持续监控。

### 73. PII (Personally Identifiable Information)

- **定义**：个人身份信息（身份证、手机号、邮箱等）。
- **风险**：LLM 可能泄露给其他用户。
- **缓解**：脱敏、加密、隔离。

### 74. Data Privacy

- **定义**：用户数据的隐私保护。
- **法规**：GDPR、CCPA、中国《个人信息保护法》。
- **实践**：数据最小化、用户可控。

### 75. Adversarial Testing

- **定义**：用对抗性输入测试 AI 系统的安全性。
- **方法**：红队测试、模糊测试、prompt 注入测试。
- **价值**：发现隐藏的安全漏洞。

### 76. Red Teaming

- **定义**：模拟攻击者测试 AI 系统。
- **目的**：发现漏洞、测试防御。
- **应用**：LLM 安全测试。

### 77. Bias

- **定义**：AI 系统对特定群体的不公平倾向。
- **类型**：性别偏见、地域偏见、年龄偏见。
- **检测**：Bias benchmark、统计检验。

### 78. Hallucination Mitigation

- **定义**：减少 LLM 幻觉的技术。
- **方法**：RAG、答案验证、Constitutional AI、人工审核。
- **关键**：不能完全消除，只能降低概率。

### 79. Output Filtering

- **定义**：过滤 LLM 输出中的有害内容。
- **方法**：关键词过滤、分类模型、人工 review。
- **应用**：所有面向用户的 LLM 应用。

### 80. Compliance

- **定义**：合规性，遵守法规和行业标准。
- **法规**：欧盟 AI Act、美国 EO 14110、中国《生成式 AI 服务管理办法》。
- **实践**：合规审查、文档化、可追溯。

## 七、商业与产品（10 个）

### 81. PMF (Product-Market Fit)

- **定义**：产品与市场的匹配度。
- **标志**：用户主动推荐、留存高、复购率高。
- **AI 时代**：比传统 SaaS 更难定义。

### 82. Copilot vs Autopilot vs Agent

- **定义**：AI 产品的三个阶段。
- **Copilot**：AI 辅助人（决策权在人）。
- **Autopilot**：AI 主驾（决策权在 AI，关键节点人把关）。
- **Agent**：AI 自主（决策权在 AI）。

### 83. Vertical AI / Vertical Agent

- **定义**：专注特定垂直场景的 AI 产品。
- **对比**：通用 AI（如 ChatGPT）。
- **优势**：ROI 清晰、护城河可见。

### 84. AI Wrapper

- **定义**：基于 OpenAI API 包装的产品。
- **风险**：没有护城河。
- **出路**：垂直深度 + 数据飞轮 + 工程能力。

### 85. Token Economics

- **定义**：基于 token 消耗的商业逻辑。
- **挑战**：用户用得越多，AI 成本越高（如果按调用收费）。
- **演进**：按席位 → 按任务 → 按结果。

### 86. Data Flywheel

- **定义**：用户使用 → 产生数据 → 优化模型 → 更好体验 → 更多用户。
- **关键**：数据必须能被模型利用。
- **代表**：法律 AI、医疗 AI（垂直深度 + 数据）。

### 87. Cold Start Problem

- **定义**：新产品没有用户、没有数据，难以起步。
- **解决**：先用通用 LLM + 人工审核，积累数据后优化。

### 88. AI Native vs AI Feature

- **定义**：AI 原生应用 vs 给传统产品加 AI 功能。
- **AI Native**：从第一天假设"Agent 是使用者之一"。
- **AI Feature**：在 UI 上加 AI 按钮。
- **未来**：AI Native 才是终态。

### 89. AGI (Artificial General Intelligence)

- **定义**：通用人工智能，能在大多数智力任务上达到或超过人类水平。
- **争议**：定义不统一、时间表不可预测。
- **务实**：关注"局部 AGI"（垂直场景）更实际。

### 90. Local AGI

- **定义**：在某个垂直场景下达到"超人类水平"的 AI。
- **三标准**：能力、稳定性、规模化。
- **未来 3-5 年**：客服、初级编程、内容生成等场景会先达到。

## 八、前沿概念（10 个）

### 91. Mamba / SSM

- **定义**：状态空间模型，Transformer 的潜在替代。
- **优势**：长序列处理（百万 token）+ 高效推理。
- **代表**：Mamba、RWKV、RetNet。

### 92. Multimodal

- **定义**：多模态（文本 + 图像 + 音频 + 视频）。
- **代表**：GPT-4V、Gemini、Claude 3.5 Sonnet。
- **应用**：图像理解、视频分析、跨模态检索。

### 93. Embodied AI

- **定义**：具身智能，AI 控制物理实体（机器人）。
- **代表**：Tesla Optimus、Figure 01。
- **挑战**：物理世界的不确定性。

### 94. World Model

- **定义**：AI 对物理世界的内部模型。
- **代表**：Sora（视频生成模型隐含世界模型）。
- **应用**：自动驾驶、机器人、决策。

### 95. Synthetic Data

- **定义**：用 AI 生成的数据训练 AI。
- **应用**：数据稀缺场景（医疗、工业）。
- **风险**：可能放大偏见。

### 96. Self-Play

- **定义**：AI 与自己对抗 / 协作以提升能力。
- **代表**：AlphaGo、AlphaZero。
- **应用**：Agent 训练、内容生成。

### 97. Distillation

- **定义**：用大模型的输出训练小模型。
- **目的**：保留大部分能力，大幅降低成本。
- **代表**：DistillWhisper、Phi-3（Mini）。

### 98. Constitutional AI

- **定义**：用"宪法"原则自我约束的 AI。
- **代表**：Anthropic Claude。
- **优势**：不需要大量人工标注。

### 99. AutoML

- **定义**：自动化机器学习。
- **包括**：自动特征工程、模型选择、超参数优化。
- **AI 时代**：用 AI 设计 AI（AutoML + LLM）。

### 100. AGI Safety / Alignment

- **定义**：AGI 安全与对齐。
- **核心**：让强大 AI 系统的目标与人类一致。
- **挑战**：interpretability（可解释性）、control（可控性）、robustness（鲁棒性）。
