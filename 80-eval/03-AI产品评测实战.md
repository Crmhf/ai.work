# 03 - AI 产品评测实战

> **TL;DR**：自己搭评测体系是**AI 产品迭代的核心基础设施**。本篇给出 9 步法 + 实战案例 + 常见陷阱。

---

## 一、为什么 AI 产品必须自己搭评测

### 原因 1：通用评测不能反映业务

- **MMLU**：评估通用知识，但你的产品是"合同审查"。
- **SWE-bench**：评估代码能力，但你的产品是"客服 Agent"。
- **通用评测高分 ≠ 业务表现好**。

### 原因 2：必须快速迭代

- 改 prompt 后 → 评估效果 → 决定上线。
- 没有评测体系，每次改动都是"赌博"。

### 原因 3：回归测试

- 新版本不能破坏老功能。
- 必须有自动化测试。

### 原因 4：客观对比

- A vs B 模型 / prompt / 框架，哪个更好？
- 没有评测 = 主观判断。

## 二、9 步评测体系搭建法

### 步骤 1：定义评测目标

**示例**：

```yaml
目标：评估客服 Agent 的"问题解决能力"
指标：
  - 主指标：问题解决率（success rate）
  - 副指标：用户满意度、响应时间、错误率
场景：
  - 标准 FAQ（订单查询、退换货）
  - 中等（退款、技术问题）
  - 复杂（投诉、纠纷）
```

### 步骤 2：收集评测数据

**来源**：
- 真实用户对话（脱敏）。
- 人工合成的"理想问题"。
- 竞品的公开案例。

**数据规模**：
- MVP：50-100 条。
- 生产：500-1000 条。
- 持续更新。

**数据格式**：

```json
{
  "case_id": "faq_001",
  "category": "order_inquiry",
  "input": {
    "user_message": "我的订单什么时候发货？",
    "user_context": {"order_id": "12345"}
  },
  "expected": {
    "intent": "order_shipping_status",
    "answer_contains": ["已发货", "预计", "物流"],
    "should_escalate": false
  },
  "difficulty": "easy"
}
```

### 步骤 3：设计评测任务

每个评测问题变成 Agent 可执行的任务：


### 步骤 4：实现评测脚本

```python
class AgentEvaluator:
    def __init__(self, agent, test_cases: List[TestCase]):
        self.agent = agent
        self.test_cases = test_cases
    
    def run_all(self):
        """运行所有测试用例"""
        results = []
        for case in self.test_cases:
            scores = run_test_case(self.agent, case)
            results.append({"case": case, "scores": scores})
        return results
    
    def aggregate(self, results):
        """汇总结果"""
        total_cases = len(results)
        passed_cases = sum(1 for r in results if all(r["scores"].values()))
        
        return {
            "total": total_cases,
            "passed": passed_cases,
            "pass_rate": passed_cases / total_cases,
            "by_category": self._by_category(results),
            "by_difficulty": self._by_difficulty(results),
            "avg_response_time": self._avg_time(results),
            "failed_cases": [r for r in results if not all(r["scores"].values())]
        }
    
    def _by_category(self, results):
        from collections import defaultdict
        by_cat = defaultdict(list)
        for r in results:
            by_cat[r["case"].category].append(r)
        return {
            cat: sum(1 for r in cases if all(r["scores"].values())) / len(cases)
            for cat, cases in by_cat.items()
        }
```

### 步骤 5：跑评测

```python
# eval/run_eval.py
def main():
    agent = load_agent("config/agent.yaml")
    test_cases = load_test_cases("data/test_cases.json")
    
    evaluator = AgentEvaluator(agent, test_cases)
    results = evaluator.run_all()

    # 保存历史

    # 检查是否达标
    if summary["pass_rate"] < 0.9:
        alert(f"Pass rate {summary['pass_rate']} < 0.9!")
```

### 步骤 6：分析结果

**重点分析**：

```python
def analyze_failures(results):
    """分析失败 case"""
    failures = [r for r in results if not all(r["scores"].values())]
    
    # 按失败类型分组
    by_failure_type = defaultdict(list)
    for f in failures:
        for key, score in f["scores"].items():
            if not score:
                by_failure_type[key].append(f)
    
    return {
        "total_failures": len(failures),
        "by_failure_type": {
            k: len(v) for k, v in by_failure_type.items()
        },
        "examples": {
            k: v[:3] for k, v in by_failure_type.items()
        }
    }
```

### 步骤 7：迭代

```python
# 改进流程
def improve_agent(eval_results):
    failures = analyze_failures(eval_results)
    
    # 1. 找共同模式
    if failures["by_failure_type"].get("intent_correct", 0) > 5:
        # intent 识别有问题，加强 prompt
        update_prompt("classification", add_examples=[
            "用户说'什么时候发货' → order_shipping_status",
            "用户说'能退吗' → refund_inquiry"
        ])
    
    if failures["by_failure_type"].get("answer_complete", 0) > 5:
        # 答案不完整，调整 prompt
        update_prompt("answer_generation", add_requirement="必须包含关键信息：发货时间、物流单号、预计到达")
    
    # 2. 重新评测
    new_results = run_eval()
    
    # 3. 对比
    if new_results.pass_rate > eval_results.pass_rate:
        deploy_new_version()
    else:
        rollback()
```

### 步骤 8：回归测试

```python
def regression_test(new_version, old_version):
    """回归测试：新版本不能比旧版本差"""
    new_results = evaluate(new_version)
    old_results = evaluate(old_version)
    
    # 新版本必须满足
    assert new_results["pass_rate"] >= old_results["pass_rate"] - 0.02  # 允许 2% 波动
    
    # 特定类别不能退化
    for category, rate in old_results["by_category"].items():
        new_rate = new_results["by_category"].get(category, 0)
        assert new_rate >= rate - 0.05  # 类别允许 5% 波动
```

## 三、评测指标设计

### 自动指标（机器评估）

| 指标 | 说明 | 适用 |
|---|---|---|
| Pass rate | 通过率（所有条件满足） | 所有任务 |
| Intent accuracy | 意图识别准确率 | 分类任务 |
| Answer completeness | 答案完整性 | 内容生成 |
| No hallucination | 无幻觉 | 知识问答 |
| Response time | 响应时间 | 所有任务 |
| Token efficiency | token 效率 | 成本敏感 |

### LLM 评估（用 LLM 评估 LLM）

```python
def llm_evaluate(question, answer, expected):
    """用 LLM 评估另一个 LLM 的输出"""
    prompt = f"""
    请评估以下回答的质量。
    
    问题：{question}
    期望答案：{expected}
    实际回答：{answer}
    
    评估维度：
    1. 准确性（1-5 分）
    2. 完整性（1-5 分）
    3. 相关性（1-5 分）
    4. 流畅性（1-5 分）
    
    输出 JSON。
    """
    return json.loads(llm.generate(prompt, format="json"))
```

### 评测脚本

```python
def evaluate_customer_service_agent(agent, test_cases):
    results = []
    for case in test_cases:
        # 运行 Agent
        output = agent.run({"message": case["input"]})
        
        # 评分
        scores = {
            "intent_correct": case["expected"]["intent"] == output.get("intent"),
            "answer_keywords_present": all(
                kw in output["answer"] for kw in case["expected"]["answer_keywords"]
            ),
            "no_forbidden_words": not any(
                word in output["answer"] for word in case["expected"].get("should_not_contain", [])
            ),
            "escalation_correct": output.get("escalated", False) == case["expected"].get("should_escalate", False)
        }
        
        results.append({
            "case_id": case["case_id"],
            "category": case["category"],
            "scores": scores,
            "passed": all(scores.values())
        })
    
    # 汇总
    return {
        "total": len(results),
        "passed": sum(r["passed"] for r in results),
        "pass_rate": sum(r["passed"] for r in results) / len(results),
        "by_category": {
            cat: {
                "total": len([r for r in results if r["category"] == cat]),
                "passed": sum(1 for r in results if r["category"] == cat and r["passed"])
            }
            for cat in set(r["category"] for r in results)
        }
    }
```

## 五、A/B 测试框架

### 单变量 A/B

```python
class ABTest:
    def __init__(self, control_agent, treatment_agent, test_cases):
        self.control = control_agent
        self.treatment = treatment_agent
        self.test_cases = test_cases
    
    def run(self):
        """A/B 测试"""
        control_results = evaluate(self.control, self.test_cases)
        treatment_results = evaluate(self.treatment, self.test_cases)
        
        return {
            "control": control_results,
            "treatment": treatment_results,
            "winner": "treatment" if treatment_results["pass_rate"] > control_results["pass_rate"] else "control",
            "improvement": treatment_results["pass_rate"] - control_results["pass_rate"],
            "statistical_significance": self._t_test(control_results, treatment_results)
        }
```

### 流量切分 A/B（生产环境）

```python
def route_to_ab_test(user_id):
```

## 六、评测常见陷阱

### 陷阱 1：评测集污染

模型见过评测集（训练数据泄漏），分数虚高。

**解决**：
- 定期更新评测集。
- 用模型没见过的真实数据。
- 关注"难例"而非"平均例"。

### 陷阱 2：只看 pass rate

pass rate 0.9，但失败 case 是"高价值客户投诉"，损失巨大。

**解决**：
- 按业务价值加权。
- 不同类别分开看。

### 陷阱 3：忽视用户体验

评测通过但用户不喜欢（语气、生硬、答非所问）。

**解决**：
- LLM 评估（评估语气、流畅性）。
- 用户反馈（👍/👎）。
- NPS 调研。

### 陷阱 4：评测集太"干净"

评测集都是"理想问题"，真实问题千奇百怪。

**解决**：
- 用真实用户问题（脱敏）。
- 加入"对抗样本"（刁难问题）。
- 加入"边缘 case"。

### 陷阱 5：评测过拟合

为评测集优化 prompt，实际效果反而下降。

**解决**：
- 保留"未公开"的 holdout 测试集。
- A/B 测试真实环境。

## 七、本章关键 takeaway

- 自己搭评测体系是 AI 产品迭代的**基础设施**。
- 9 步法：定义目标 → 收集数据 → 设计任务 → 实现脚本 → 跑评测 → 分析 → 迭代 → 回归 → 定期。
- **三维评估**：自动指标 + LLM 评估 + 人工评估。
- **按业务价值加权**，避免"高分但低价值"。
- **避免 5 个陷阱**：污染、单一指标、用户体验、干净评测集、过拟合。
