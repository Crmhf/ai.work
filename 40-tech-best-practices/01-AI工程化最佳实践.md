# 01 - AI 工程化最佳实践

> **TL;DR**：AI 工程化与传统软件工程的差异在于**不确定性、可观测性、可逆性**。本篇给出 5 大原则 + 12 条实践。

---

## 一、AI 项目与传统软件项目的 5 大差异

| 维度 | 传统软件 | AI 项目 |
|---|---|---|
| 行为确定性 | 高（给定输入必输出） | 低（同样输入可能不同输出） |
| 测试方式 | 单元测试、E2E | 需要"样本测试 + 人工评估" |
| 失败模式 | 异常、错误码 | 幻觉、跑偏、不符合契约 |
| 调试 | stack trace | trace + prompt 工程 |
| 迭代周期 | 按周 | 按天（甚至按小时） |

---

## 二、AI 工程化的 5 大原则

### 原则 1：契约先于实现

传统软件可以"接口先行"，AI 项目更需要——**LLM 输出不确定，必须用契约约束**。

**实践**：
- 每个 AI 任务的输出必须有 schema 校验（JSON Schema / Pydantic）。
- 契约失败时不直接 retry，而是分析原因（模型问题 / prompt 问题 / 输入问题）。

### 原则 2：可观测性先于功能

AI 项目的 bug 通常"看不见、摸不着"。没有可观测性，无法 debug。

**实践**：
- 每个 LLM 调用记录：input、output、prompt、token、cost、latency。
- 每个 Agent 调用记录 trace。
- 监控仪表盘比产品 UI 更早上线。

### 原则 3：可逆性先于效率

AI 项目失败率比传统软件高，**先保证失败可恢复，再追求高效**。

**实践**：
- 每个写入操作都可回滚（事务、版本控制）。
- Agent 的输出默认是"建议"，需要人类确认才落地。
- 提供"撤销"按钮比提供"加速"按钮重要。

### 原则 4：协同先于自动化

AI 项目不要追求"全自动"，应该"高自动化 + 关键节点人类把关"。

**实践**：
- 风险低：全自动（查询、统计）。
- 风险中：AI 执行 + 人类审批（修改、发送）。
- 风险高：必须人类决策（删除、转账、对外）。

### 原则 5：成本与质量并重

LLM 成本很容易失控（每次调用 0.1 美元 × 1000 次/天 = 100 美元/天 = 3000 美元/月）。

**实践**：
- 每个项目有 token 预算。
- 超过预算自动降级（小模型 / 短 prompt）。
- 监控单位任务成本。

## 三、12 条实践

### 1. Prompt 必须版本化

```bash
prompts/
├── v1/
│   ├── system_prompt.txt
│   └── user_template.txt
├── v2/
└── CHANGELOG.md
```

每次 prompt 变更都进 Git，有版本号。**prompt 是 AI 项目的"代码"，必须有版本管理**。

### 2. LLM 调用必须 trace

```python
with tracer.span("llm_call", attributes={
    "model": "gpt-4",
    "prompt_version": "v2.1",
    "task_id": task_id,
}):
    response = llm.generate(prompt)
    tracer.set_attribute("tokens", response.tokens)
    tracer.set_attribute("cost_usd", response.cost)
    tracer.set_attribute("latency_ms", latency)
```

### 3. 输出必须有 schema 校验

```python
from pydantic import BaseModel, validator

class TaskOutput(BaseModel):
    summary: str
    priority: str
    
    @validator("priority")
    def validate_priority(cls, v):
        if v not in ["low", "medium", "high"]:
            raise ValueError(f"Invalid priority: {v}")
        return v
```

### 4. 输入必须清洗

LLM 输入含敏感数据（用户信息、商业机密）是常见错误。

```python
def sanitize_input(text: str) -> str:
    """清洗 LLM 输入"""
    # 移除 PII（个人身份信息）
    text = re.sub(r'\b\d{17}[\dXx]\b', '[ID_CARD]', text)  # 身份证
    text = re.sub(r'\b1[3-9]\d{9}\b', '[PHONE]', text)  # 手机号
    text = re.sub(r'[\w.-]+@[\w.-]+', '[EMAIL]', text)  # 邮箱
    return text
```

### 5. 失败必须有兜底

```python
def safe_llm_call(prompt, fallback=None):
    try:
        return llm.generate(prompt)
    except RateLimitError:
        # 降级到更便宜的模型
        return llm_cheap.generate(prompt)
    except TimeoutError:
        # 返回兜底结果
        return fallback or {"status": "unknown", "reason": "timeout"}
```

### 6. 评估必须常态化

不要等"项目上线"才评估，**每次 prompt 变更都要跑评估**。

```python
# eval/run_eval.py
def run_eval():
    test_cases = load_test_cases()
    results = []
    
    for case in test_cases:
        output = run_pipeline(case.input)
        passed = evaluate(output, case.expected)
        results.append({"case": case.id, "passed": passed, "output": output})
    
    pass_rate = sum(r["passed"] for r in results) / len(results)
    print(f"Pass rate: {pass_rate * 100}%")
    
    if pass_rate < 0.9:
        # 质量不达标，告警
        alert("Quality regression detected!")
```

### 7. 缓存必须合理

```python
# 缓存热点 query（节省成本 + 提速）
@cached(ttl=3600)
def get_user_info(user_id):
    return llm.generate(f"提取用户 {user_id} 的关键信息")
```

但要谨慎：**缓存可能让 AI 输出失去个性化**。

### 8. 重试必须有上限

```python
def retry_with_backoff(fn, max_retries=3):
    for attempt in range(max_retries):
        try:
            return fn()
        except (RateLimitError, TimeoutError) as e:
            if attempt == max_retries - 1:
                raise
            time.sleep(2 ** attempt)  # 指数退避
```

### 9. Token 预算必须监控

```python
class TokenBudget:
    def __init__(self, daily_limit: int):
        self.daily_limit = daily_limit
        self.used = 0
    
    def check(self, tokens: int):
        if self.used + tokens > self.daily_limit:
            raise BudgetExceeded("Daily token budget exceeded")
        self.used += tokens
```

### 10. 错误信息必须友好

LLM 的错误信息往往很技术，用户看不懂。

```python
def user_friendly_error(error):
    if isinstance(error, RateLimitError):
        return "系统繁忙，请稍后重试"
    if isinstance(error, ContentFilteredError):
        return "内容不符合规范，请修改后重试"
    if isinstance(error, LLMError):
        return "AI 处理失败，已记录并由工程师跟进"
    return "未知错误"
```

### 11. 模型切换必须可配置

```python
# config/llm.yaml
default_model: gpt-4
fallback_chain:
  - gpt-4
  - gpt-4-turbo
  - gpt-3.5-turbo
  - claude-3-sonnet
```

不要硬编码模型名，方便切换和降级。

### 12. Prompt 必须 A/B 测试

```python
def ab_test_prompt(prompt_a, prompt_b, test_cases):
    results_a = [run_pipeline(prompt_a, case) for case in test_cases]
    results_b = [run_pipeline(prompt_b, case) for case in test_cases]
    
    score_a = evaluate_batch(results_a, test_cases)
    score_b = evaluate_batch(results_b, test_cases)
    
    if score_b > score_a:
        print(f"Prompt B is better: {score_a} → {score_b}")
        return prompt_b
    return prompt_a
```

## 四、必须避免的反模式

### 反模式 1：硬编码 prompt 在代码里

```python
# ❌ 错误
response = llm.generate(f"你是产品经理。请写一个 PRD，关于{feature}。要求包含用户故事和验收标准。")
```

prompt 应该独立管理（文件 / 数据库 / 配置中心），方便版本化和 A/B 测试。

### 反模式 2：无 schema 校验

```python
# ❌ 错误
output = llm.generate(prompt)
# 直接用 output.field，假设结构正确
process(output)
```

LLM 输出可能不符合契约，必须有 schema 校验。

### 反模式 3：忽略错误日志

```python
# ❌ 错误
try:
    output = llm.generate(prompt)
except Exception:
    pass  # 吞掉错误
```

错误必须记录，否则无法调试。

### 反模式 4：模型选择看心情

```python
# ❌ 错误：今天用 GPT-4，明天用 Claude
output = random.choice([gpt4, claude, llama]).generate(prompt)
```

模型切换必须有依据（成本、能力、可用性），且 A/B 测试。

### 反模式 5：无人工评估

只靠自动指标（pass rate），不靠人工 spot check。**LLM 评测必须人机结合**。

---

## 五、本章关键 takeaway

- AI 工程化 5 大原则：契约、可观测、可逆、协同、成本。
- 12 条实践：版本化、trace、校验、清洗、兜底、评估、缓存、重试、预算、友好错误、模型可配、A/B 测试。
- 5 个反模式：硬编码、无校验、吞错误、随机模型、无人工评估。
- **AI 项目不是"调 prompt"，是"工程化 prompt"**。
