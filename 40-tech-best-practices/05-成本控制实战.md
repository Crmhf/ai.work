# 05 - 成本控制实战

> **TL;DR**：LLM 成本是最容易被忽视的"灾难"——一个未优化的 Agent 系统每月可能烧掉 **$3,000+**。本篇给出 **9 个实战技巧**，从模型选择、缓存、批处理、监控 4 个维度把成本压到 1/5。

---

## 一、成本失控的真实案例

### 案例 1：未优化的客服 Agent

- **场景**：每天 10,000 次对话。
- **每次成本**：$0.05（GPT-4 + 长 prompt）。
- **月成本**：$0.05 × 10,000 × 30 = **$15,000**。
- **优化后**：$0.01（GPT-3.5 + 缓存 + 短 prompt）。
- **月成本**：$0.01 × 10,000 × 30 = **$3,000**。
- **节省**：80%。

### 案例 2：未监控的 Agent

- **场景**：某个 Agent 进入死循环，30 分钟内调用 LLM **5,000 次**。
- **单次成本**：$0.03。
- **单次故障成本**：$150。
- **月发生 3 次**：$450 浪费。

## 三、9 个成本控制技巧

### 技巧 1：分级使用模型

**核心思想**：**简单任务用便宜模型，复杂任务用贵模型**。

```python
class TieredLLMClient:
    def __init__(self):
        self.models = {
            "cheap": "gpt-3.5-turbo",       # $0.0005/$0.0015
            "balanced": "gpt-4-turbo",      # $0.01/$0.03
            "expensive": "gpt-4",           # $0.03/$0.06
        }
    
    def generate(self, prompt, complexity="balanced"):
        model = self.models[complexity]
        return llm_client.generate(model, prompt)

# 使用
# 简单分类 → cheap
# 通用任务 → balanced
# 复杂推理 → expensive
```

**典型配置**：

| 任务类型 | 推荐模型 | 单次成本 |
|---|---|---|
| 文本分类 | gpt-3.5-turbo | $0.001 |
| 实体提取 | gpt-3.5-turbo | $0.002 |
| 内容总结 | gpt-4-turbo | $0.01 |
| 代码生成 | gpt-4 | $0.05 |
| 复杂推理 | gpt-4 | $0.10 |

### 技巧 2：Prompt 精简

**核心思想**：**减少 input tokens** 是降本最直接的方法。

```python
# ❌ 差：500 字 prompt
long_prompt = """
你是专业的客服 AI，你的职责是回答用户的问题。
你需要遵循以下原则：
1. ...
2. ...
[500 字详细说明]
用户问题：{question}
"""

# ✅ 好：100 字 prompt
short_prompt = """
你是客服 AI。简洁、专业、友好。
用户问题：{question}
回答：
"""
```

**实测**：500 字 → 100 字，输入 token 减少 80%，单次成本降低 60%。

### 技巧 3：缓存（最重要！）

**核心思想**：**相同 query 的响应缓存起来**，重复利用。

```python
import hashlib

class CachedLLMClient:
    def __init__(self, redis_client):
        self.redis = redis_client
        self.cache_ttl = 3600  # 1 小时
    
    def generate(self, prompt, model="gpt-4"):
        # 1. 计算 cache key
        cache_key = f"llm:{model}:{hashlib.md5(prompt.encode()).hexdigest()}"
        
        # 2. 查缓存
        cached = self.redis.get(cache_key)
        if cached:
            return json.loads(cached)
        
        # 3. 未命中，调 LLM
        response = llm_client.generate(model, prompt)
        
        # 4. 写缓存
        self.redis.setex(cache_key, self.cache_ttl, json.dumps(response))
        
        return response
```

**实测效果**：
- FAQ 类 query 命中率 60%+。
- 节省成本 50%+。

### 技巧 4：批处理

**核心思想**：**多个相似任务合并到一个 prompt**。

```python
# ❌ 差：10 次 LLM 调用
for comment in comments:
    sentiment = llm.generate(f"分析评论情感：{comment}")
    
# ✅ 好：1 次 LLM 调用
batch_prompt = "请分析以下 10 条评论的情感，每行一条，输出 JSON 列表：\n"
for i, comment in enumerate(comments):
    batch_prompt += f"{i+1}. {comment}\n"
results = llm.generate(batch_prompt)
```

**节省**：10 次调用 → 1 次调用，成本降低 70%+。

### 技巧 5：限制 max_tokens

```python
# ❌ 差：不限制，LLM 可能生成 4000 tokens
response = llm.generate(prompt)

# ✅ 好：限制 max_tokens
response = llm.generate(prompt, max_tokens=500)
```

如果只需要 200 字回答，限制 max_tokens=300 可以避免 LLM "啰嗦"。

### 技巧 6：温度调节

```python
# 高温度（如创意任务）：成本略高（更多次采样）
response = llm.generate(prompt, temperature=0.9)

# 低温度（如精确任务）：成本低
response = llm.generate(prompt, temperature=0.0)
```

但温度对成本的影响相对较小，主要影响质量。

### 技巧 7：流式响应按需

```python
# ❌ 差：等 LLM 生成完整响应（用户等待 + 大量 token）
response = llm.generate(prompt)  # 等待 30s
return response

# ✅ 好：流式（用户体验好，可能提前终止）
def stream_generate(prompt):
    accumulated = ""
    for chunk in llm.stream_generate(prompt):
        accumulated += chunk.text
        yield chunk.text
        
        # 用户提前停止？终止生成
        if user_stopped():
            break
```

如果用户提前停止，可能节省 50%+ 的成本。

### 技巧 8：监控与告警

```python
class CostMonitor:
    def __init__(self, daily_budget: float):
        self.daily_budget = daily_budget
        self.daily_cost = 0
    
    def record_call(self, model: str, input_tokens: int, output_tokens: int):
        cost = self._calculate_cost(model, input_tokens, output_tokens)
        self.daily_cost += cost
        
        # 预算告警
        if self.daily_cost > self.daily_budget * 0.8:
            alert(f"每日成本已达预算 80%: ${self.daily_cost:.2f}")
        
        if self.daily_cost > self.daily_budget:
            raise BudgetExceeded("Daily budget exceeded")
    
    def _calculate_cost(self, model, input_tokens, output_tokens):
        prices = {
            "gpt-4": (0.03, 0.06),
            "gpt-4-turbo": (0.01, 0.03),
            "gpt-3.5-turbo": (0.0005, 0.0015),
        }
        input_price, output_price = prices[model]
        return (input_tokens / 1000) * input_price + (output_tokens / 1000) * output_price
```

### 技巧 9：避免死循环

```python
class SafeAgentLoop:
    def __init__(self, max_iterations=10, max_cost=0.5):
        self.max_iterations = max_iterations
        self.max_cost = max_cost
        self.iteration_count = 0
        self.total_cost = 0
    
    def step(self, fn):
        self.iteration_count += 1
        
        if self.iteration_count > self.max_iterations:
            raise MaxIterationsExceeded()
        
        result = fn()
        self.total_cost += result.cost
        
        if self.total_cost > self.max_cost:
            raise MaxCostExceeded()
        
        return result
```

- **成本预算**：预算紧张选便宜模型。

## 七、我的实战经验

### 经验 1：缓存是降本最大杠杆

很多 LLM 调用是**重复或相似的**。我自己的项目**缓存命中率 65%+**，节省成本 50%+。

### 经验 2：Prompt 越短越好

我曾经有一个 800 字的 prompt，重写为 200 字后**效果相同**但成本降低 60%。

### 经验 3：流式响应救我很多次

用户经常在看到前 100 字就停止滚动。流式响应 + 提前终止，每次平均节省 40% 输出成本。

### 经验 4：监控 + 告警必须上

我曾经因为一个 Agent 进入死循环，**30 分钟烧掉 $200**。之后我加了 max_iterations 和成本告警。

### 经验 5：分级使用模型

不要"所有任务都用 GPT-4"。**70% 的任务可以用 GPT-3.5**，质量影响很小。
