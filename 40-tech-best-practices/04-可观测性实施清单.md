# 04 - 可观测性实施清单

> **TL;DR**：AI Agent 项目的可观测性比传统软件**更难、更重要**。本篇给出 **30 项可观测性检查点**，从日志、Trace、Metrics、告警、调试工具 5 个维度全面覆盖。

---

## 一、为什么 AI 项目更需要可观测性

| 维度 | 传统软件 | AI Agent 项目 |
|---|---|---|
| Bug 可见性 | 高（异常、错误码） | 低（幻觉、跑偏、无报错） |
| 重现性 | 高 | 低（同样输入可能不同输出） |
| 调试信息 | Stack trace | prompt、context、token、cost |
| 失败模式 | 明确 | 模糊（"输出不太对"） |

**没有可观测性的 AI 项目 = 黑盒跑生产**。

## 二、30 项可观测性检查点

### A. 日志（10 项）

#### A1. 每次 LLM 调用都有结构化日志

```python
logger.info("llm_call", extra={
    "model": "gpt-4",
    "prompt_version": "v2.1",
    "task_id": task_id,
    "user_id": user_id,
    "tokens_input": 1500,
    "tokens_output": 800,
    "cost_usd": 0.069,
    "latency_ms": 2300,
    "status": "success"
})
```

#### A2. 每次 Tool 调用都有日志

```python
logger.info("tool_call", extra={
    "tool_name": "search",
    "tool_args_hash": hashlib.md5(json.dumps(args).encode()).hexdigest(),
    "result_size": len(result),
    "latency_ms": 200
})
```

#### A3. 每个 Agent 调用都有日志

```python
logger.info("agent_call", extra={
    "agent_id": "product_agent",
    "task_id": task_id,
    "input_summary": summary,
    "output_summary": summary,
    "duration_seconds": 30
})
```

#### A4. 失败都有详细错误日志

```python
try:
    response = llm.generate(prompt)
except Exception as e:
    logger.error("llm_call_failed", extra={
        "error_type": type(e).__name__,
        "error_message": str(e),
        "prompt": prompt[:500],  # 截断避免日志过大
        "model": model_name
    }, exc_info=True)
```

#### A5. 重要决策都有决策日志

```python
logger.info("decision_made", extra={
    "decision_type": "task_routing",
    "decision": "assigned_to_agent_coder",
    "reason": "task complexity high",
    "confidence": 0.92
})
```

#### A6. 用户交互都有日志

```python
logger.info("user_interaction", extra={
    "user_id": user_id,
    "session_id": session_id,
    "input_summary": summary,
    "response_summary": summary,
    "satisfaction_signal": feedback
})
```

#### A7. Prompt 版本都记录

```python
logger.info("prompt_used", extra={
    "prompt_name": "customer_classifier",
    "prompt_version": "v2.1",
    "prompt_hash": hashlib.md5(prompt.encode()).hexdigest()
})
```

#### A8. PII 字段在日志中脱敏

```python
def sanitize_for_log(data):
    if isinstance(data, dict):
        return {k: "***" if k in PII_FIELDS else sanitize_for_log(v) for k, v in data.items()}
    # ...
```

#### A9. 日志按 trace_id 索引

```python
trace_id = generate_trace_id()
logger = logger.bind(trace_id=trace_id)
```

#### A10. 日志保留策略明确

- INFO 日志保留 30 天。
- ERROR 日志保留 90 天。
- 关键决策日志保留 1 年。

### B. Trace（5 项）

#### B1. 所有跨服务调用都用 OpenTelemetry

```python
from opentelemetry import trace

tracer = trace.get_tracer(__name__)

with tracer.start_as_current_span("process_request") as span:
    span.set_attribute("user_id", user_id)
    
    with tracer.start_as_current_span("llm_call") as llm_span:
        response = llm.generate(prompt)
        llm_span.set_attribute("model", "gpt-4")
        llm_span.set_attribute("tokens", response.tokens)
```

#### B2. 每个 Span 都有有意义的属性

```python
span.set_attribute("agent.name", "orchestrator")
span.set_attribute("task.id", task_id)
span.set_attribute("task.complexity", "high")
span.set_attribute("llm.model", "gpt-4")
span.set_attribute("llm.tokens", response.tokens)
span.set_attribute("llm.cost_usd", response.cost)
```

#### B3. Trace 包含完整链路

```
用户请求 → API Gateway → Orchestrator → Task Decomposition → LLM Call
                                              ↓
                                         Specialist Agent → LLM Call
                                              ↓
                                         Tool Call
                                              ↓
                                         Quality Gate
                                              ↓
                                         Response
```

#### B4. Span 之间有父子关系

```python
with tracer.start_as_current_span("parent_task") as parent:
    with tracer.start_as_current_span("child_step_1") as child1:
        ...
    with tracer.start_as_current_span("child_step_2") as child2:
        ...
```

#### B5. 长 Span 自动标记

```python
# 超过 30 秒的 span 自动标记为 slow
if span.duration > 30:
    span.set_attribute("slow", True)
    alert("Slow span detected")
```

### D. 告警（5 项）

#### D1. 错误率告警

```yaml
- name: "LLMErrorRateHigh"
  condition: "rate(errors_total{component='llm'}[5m]) / rate(llm_calls_total[5m]) > 0.1"
  severity: "critical"
  message: "LLM 错误率超过 10%"
  action: "page_oncall"
```

#### D2. 成本告警

```yaml
- name: "DailyCostOverBudget"
  condition: "increase(cost_usd_total[1d]) > 100"
  severity: "warning"
  message: "每日成本已超过 $100"
```

#### D3. 延迟告警

```yaml
- name: "LLMLatencyHigh"
  condition: "quantile(0.95, llm_latency_seconds[5m]) > 10"
  severity: "warning"
  message: "LLM 调用延迟 p95 > 10s"
```

#### D4. 质量告警

```yaml
- name: "QualityGateFailureRateHigh"
  condition: "rate(quality_gate_result_total{result='failed'}[10m]) / rate(quality_gate_result_total[10m]) > 0.2"
  severity: "critical"
  message: "质量门禁失败率超过 20%"
```

#### D5. 健康告警

```yaml
- name: "ServiceDown"
  condition: "up == 0"
  severity: "critical"
  message: "服务不可用"
  action: "page_oncall"
```

### E. 调试工具（2 项）

#### E1. Prompt Playground

支持在线测试不同 prompt 版本的工具：

```python
# /admin/prompt-playground
@app.post("/admin/prompt-playground")
def prompt_playground(prompt_version, test_cases):
    template = load_template(prompt_version)
    results = []
    for case in test_cases:
        prompt = render(template, case.input)
        output = llm.generate(prompt)
        results.append({"input": case.input, "output": output, "expected": case.expected})
    return results
```

## 三、可观测性技术栈

### 推荐组合

```
日志：ELK（Elasticsearch + Logstash + Kibana）或 Loki + Grafana
Trace：OpenTelemetry + Jaeger / Tempo
Metrics：Prometheus + Grafana
告警：Alertmanager + PagerDuty / 飞书 / 钉钉
```

### 实施顺序

```
阶段 1（必须）：
- 结构化日志（A1, A4, A9）
- 基础 Trace（B1, B2）
- 错误告警（D1, D5）

阶段 2（重要）：
- 完整 Trace（B3, B4）
- 性能 Metrics（C1, C2）
- 延迟告警（D3）

阶段 3（建议）：
- 业务 Metrics（C5）
- 成本 Metrics（C3）
- 调试工具（E1, E2）

阶段 4（高级）：
- Span 自动标记（B5）
- 用户指标（C5）
- 高级告警（D2, D4）
```

## 四、常见可观测性陷阱

### 陷阱 1：日志太大

每次 LLM 调用都打印完整 prompt 和 response，**日志爆炸**。

**解决**：截断 + 摘要。
```python
logger.info("llm_call", extra={
    "prompt": prompt[:500],  # 只记录前 500 字
    "response_summary": response[:200],
    "full_response_in_s3": s3_url  # 完整内容存 S3
})
```

### 陷阱 2：Token 在日志中泄露

```python
# ❌ 错误
logger.info(f"API call with token: {api_token}")

# ✅ 正确
logger.info(f"API call", extra={"token_hash": hash(api_token)})
```

### 陷阱 3：PII 不脱敏

```python
# 必须在日志中间件里强制脱敏
class SanitizingFilter(logging.Filter):
    def filter(self, record):
        record.msg = sanitize_pii(record.msg)
        return True
```

### 陷阱 4：指标爆炸

```python
# ❌ 错误：每个 user_id 都作为 label
USER_REQUESTS.labels(user_id=user_id).inc()
# 100 万 user × 10 个 label = 1000 万时间序列

# ✅ 正确：聚合
USER_REQUESTS.labels(user_type="free").inc()
```

### 陷阱 5：告警疲劳

```python
# ❌ 错误：每次失败都告警
if error:
    alert()

# ✅ 正确：阈值 + 抑制
if rate(errors[5m]) > 0.1:
    alert()
# 同样的告警 5 分钟内只发一次
```

## 五、本章关键 takeaway

- 30 项检查点覆盖日志（10）、Trace（5）、Metrics（8）、告警（5）、调试工具（2）。
- 实施分 4 阶段：必须 → 重要 → 建议 → 高级。
- 推荐技术栈：ELK + OpenTelemetry + Prometheus + Grafana + Alertmanager。
- 避免 5 个陷阱：日志太大、Token 泄露、PII 不脱敏、指标爆炸、告警疲劳。
- **没有可观测性的 AI 项目 = 黑盒跑生产**。
