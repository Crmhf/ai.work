# 03 - 妙记 AI 产物提取实战

> **TL;DR**：妙记 AI 产物 API 是飞书会议自动化最关键的能力，**只在自建应用下可用**。它把会议语音转成 summary / todo_list / sections 三类结构化输出，准确率 95%+。实战关键是**轮询 + 解析 + 容错**。

---

## 一、妙记 AI 产物的三类输出

飞书妙记在会议结束后会自动处理音视频，生成三类结构化 AI 产物：

### 1. summary（纪要总结）

会议的整体总结，自然语言描述，通常 200-500 字。

**示例**：
> "本次周会讨论了 Q3 OKR 进度，重点对齐了客户 A 的需求变更对排期的影响，决定将原定 9 月 15 日上线的功能 A 推迟到 9 月 25 日，并由产品同学王五负责通知客户。会议还讨论了系统稳定性问题，决定本周内完成核心服务的限流改造，由后端李四负责。"

### 2. todo_list（待办事项清单）

从会议中提取的结构化待办列表，每项包含：
- **content**：待办内容
- **owner**：负责人（如果有）
- **due**：截止时间（如果有）
- **priority**：优先级（如果有）

**示例**：
```json
[
  {
    "content": "通知客户 A 功能推迟到 9/25",
    "owner": "王五",
    "due": "2026-09-16",
    "priority": "high"
  },
  {
    "content": "完成核心服务限流改造",
    "owner": "李四",
    "due": "2026-09-20",
    "priority": "high"
  }
]
```

**准确率 95%+**，是会议场景天然的结构化入口。

### 3. sections（章节划分索引）

按议题/时间段切分的章节，每个章节包含时间戳和简要描述。

**示例**：
```json
[
  {"title": "Q3 OKR 进度对齐", "start_time": "10:00", "end_time": "10:25", "summary": "..."},
  {"title": "客户 A 需求变更讨论", "start_time": "10:25", "end_time": "10:50", "summary": "..."},
  {"title": "系统稳定性问题", "start_time": "10:50", "end_time": "11:15", "summary": "..."}
]
```

## 二、妙记 API 详解

### 核心端点

```
GET https://open.feishu.cn/open-apis/minutes/v1/minutes/:minute_token/artifacts
```

**关键参数**：
- `minute_token`：妙记 ID，从会议结束事件的 payload 中获取
- 权限：`minutes:minutes:readonly`

**响应示例**：

```json
{
  "code": 0,
  "msg": "success",
  "data": {
    "summary": "本次周会讨论了...",
    "todo_list": [
      {
        "content": "通知客户 A 功能推迟",
        "owner": {"id": "ou_xxx", "name": "王五"},
        "due": "2026-09-16",
        "priority": "high"
      }
    ],
    "sections": [
      {"title": "Q3 OKR 进度对齐", "start_time": "10:00", "end_time": "10:25"}
    ],
    "generate_time": "2026-06-21T11:30:00Z",
    "version": 1
  }
}
```

### 调用频率限制

- **妙记 AI 产物 API：5 QPS**
- 妙记处理时间：**会议结束后 5-30 分钟**

这意味着：
- 不能会议一结束就立刻调用，必须**等待妙记处理完成**。
- 实际实现需要**轮询机制**：每 2-3 分钟查询一次，直到拿到产物或超时。

## 三、完整调用链示例

```python
import asyncio
import time
from datetime import datetime, timedelta
from lark_oapi import Client
from lark_oapi.api.minutes.v1 import *

class MinutesArtifactExtractor:
    """妙记 AI 产物提取器"""
    
    def __init__(self, app_id: str, app_secret: str):
        self.client = Client.builder() \
            .app_id(app_id).app_secret(app_secret).build()
    
    async def extract_with_retry(
        self,
        minute_token: str,
        max_wait_minutes: int = 30,
        poll_interval_seconds: int = 120
    ) -> MinutesArtifact:
        """
        轮询获取妙记 AI 产物
        
        Args:
            minute_token: 妙记 ID
            max_wait_minutes: 最大等待时间（妙记 AI 处理时间）
            poll_interval_seconds: 轮询间隔
        """
        start_time = datetime.now()
        deadline = start_time + timedelta(minutes=max_wait_minutes)
        
        while datetime.now() < deadline:
            artifact = await self._try_extract(minute_token)
            
            if artifact and self._is_complete(artifact):
                return artifact
            
            # 等待下次轮询
            await asyncio.sleep(poll_interval_seconds)
        
        # 超时未获取到完整产物
        raise TimeoutError(
            f"妙记 AI 产物在 {max_wait_minutes} 分钟内未生成完整结果"
        )
    
    async def _try_extract(self, minute_token: str) -> Optional[MinutesArtifact]:
        """单次尝试获取产物"""
        try:
            req = GetMinutesArtifactRequest.builder() \
                .minute_token(minute_token) \
                .build()
            
            resp = self.client.minutes.v1.minutes_artifact.get(req)
            
            if not resp.success():
                # 妙记还在处理中（返回特定错误码）
                if resp.code == 231001:  # 妙记处理中
                    return None
                else:
                    raise MinutesAPIError(resp.code, resp.msg)
            
            artifact_data = resp.data.artifact
            artifact = self._parse_artifact(artifact_data)
            return artifact
        
        except Exception as e:
            # 网络错误，等待重试
            print(f"妙记 API 调用异常: {e}")
            return None
    
    def _is_complete(self, artifact: MinutesArtifact) -> bool:
        """判断妙记 AI 产物是否完整"""
        return (
            artifact.summary is not None and
            artifact.todo_list is not None and
            artifact.sections is not None
        )
    
    def _parse_artifact(self, data: Dict) -> MinutesArtifact:
        """解析 API 响应为内部数据结构"""
        todo_list = []
        for todo in data.get("todo_list", []):
            todo_list.append(TodoItem(
                content=todo.get("content", ""),
                owner_id=todo.get("owner", {}).get("id"),
                owner_name=todo.get("owner", {}).get("name"),
                due=todo.get("due"),
                priority=todo.get("priority", "medium")
            ))
        
        sections = []
        for sec in data.get("sections", []):
            sections.append(Section(
                title=sec.get("title", ""),
                start_time=sec.get("start_time"),
                end_time=sec.get("end_time"),
                summary=sec.get("summary")
            ))
        
        return MinutesArtifact(
            minute_token=data.get("minute_token"),
            summary=data.get("summary", ""),
            todo_list=todo_list,
            sections=sections,
            generate_time=data.get("generate_time"),
            version=data.get("version", 1)
        )


@dataclass
class TodoItem:
    content: str
    owner_id: Optional[str]
    owner_name: Optional[str]
    due: Optional[str]
    priority: str  # low / medium / high


@dataclass
class Section:
    title: str
    start_time: str
    end_time: str
    summary: Optional[str]


@dataclass
class MinutesArtifact:
    minute_token: str
    summary: str
    todo_list: List[TodoItem]
    sections: List[Section]
    generate_time: str
    version: int
```

## 四、从妙记到任务的关键转换

提取出妙记产物后，需要把 `todo_list` 转换成飞书任务。转换逻辑：

### 1. 负责人匹配

妙记提取的负责人是**自然语言名字**（如"王五"），需要转成飞书的 open_id。

```python
async def resolve_owner_to_open_id(self, owner_name: str) -> Optional[str]:
    """把名字转成 open_id"""
    # 1. 先查企业通讯录
    req = SearchUserRequest.builder() \
        .query(owner_name) \
        .build()
    resp = self.client.contact.v3.user.search(req)
    
    if resp.success() and resp.data.items:
        # 2. 选最匹配的一个（精确匹配优先）
        for user in resp.data.items:
            if user.name == owner_name:
                return user.open_id
        # 没有精确匹配，返回第一个
        return resp.data.items[0].open_id
    
    # 3. 找不到，标记为未分配
    return None
```

### 2. 截止时间解析

妙记返回的 due 是字符串（如 "2026-09-16"），需要转成飞书任务 API 要求的毫秒时间戳。

```python
from datetime import datetime

def parse_due_to_timestamp(self, due_str: str) -> Optional[int]:
    """解析截止时间字符串为毫秒时间戳"""
    if not due_str:
        return None
    
    # 尝试多种格式
    formats = [
        "%Y-%m-%d",
        "%Y/%m/%d",
        "%Y年%m月%d日",
        "%m-%d",
        "明天",
        "下周"
    ]
    
    # 简化：只支持 ISO 日期
    try:
        dt = datetime.strptime(due_str, "%Y-%m-%d")
        return int(dt.timestamp() * 1000)
    except ValueError:
        # 模糊日期（如"明天"），用规则推断
        return self._parse_relative_date(due_str)

def _parse_relative_date(self, text: str) -> Optional[int]:
    """解析相对日期"""
    today = datetime.now()
    
    if "今天" in text:
        target = today
    elif "明天" in text:
        target = today + timedelta(days=1)
    elif "后天" in text:
        target = today + timedelta(days=2)
    elif "下周" in text:
        target = today + timedelta(days=7)
    elif "下个月" in text:
        target = today + timedelta(days=30)
    else:
        return None
    
    return int(target.timestamp() * 1000)
```

### 3. 创建任务（含 origin 溯源）

```python
async def create_task_from_todo(
    self,
    todo: TodoItem,
    minute_token: str,
    meeting_id: str,
    bitable_record_id: str
) -> str:
    """从妙记 todo 创建飞书任务"""
    
    # 1. 解析负责人
    owner_open_id = await self.resolve_owner_to_open_id(todo.owner_name)
    
    # 2. 解析截止时间
    due_timestamp = self.parse_due_to_timestamp(todo.due)
    
    # 3. 构造 origin 字段（关键！用于溯源）
    origin = {
        "source": "minutes_artifact",
        "minute_token": minute_token,
        "meeting_id": meeting_id,
        "bitable_record_id": bitable_record_id,
        "extracted_at": datetime.utcnow().isoformat(),
        "raw_content": todo.content  # 保留原始提取内容
    }
    
    # 4. 创建任务
    req = CreateTaskRequest.builder() \
        .request_body(
            CreateTaskRequestBody.builder()
            .summary(todo.content[:200])  # 任务标题
            .description(
                f"从妙记 AI 提取的待办事项\n\n"
                f"**原始内容**: {todo.content}\n"
                f"**来源会议**: {meeting_id}\n"
                f"**妙记**: {minute_token}\n"
                f"**关联多维表格记录**: {bitable_record_id}"
            )
            .due(
                TaskDue.builder()
                .timestamp(str(due_timestamp))
                .is_all_day(False)
                .build()
            )
            .origin(json.dumps(origin, ensure_ascii=False))  # 关键字段
            .assignees(
                [TaskAssignee.builder().id(owner_open_id).build()]
                if owner_open_id else []
            )
            .priority(self._map_priority(todo.priority))
            .build()
        ).build()
    
    resp = self.client.task.v2.task.create(req)
    
    if resp.success():
        return resp.data.task.guid
    else:
        raise TaskCreationError(resp.code, resp.msg)

def _map_priority(self, priority: str) -> str:
    """映射优先级"""
    mapping = {
        "low": "low",
        "medium": "medium",
        "high": "high",
        "urgent": "urgent"
    }
    return mapping.get(priority, "medium")
```

## 五、智能纪要内容解析

妙记 summary 是自然语言文本，需要进一步解析（如提取关键决策、风险点）。

```python
async def analyze_summary(self, summary: str) -> SummaryAnalysis:
    """用 LLM 分析会议总结"""
    prompt = f"""
    分析以下会议纪要总结，提取关键信息：
    
    总结：
    {summary}
    
    输出 JSON 格式：
    {{
        "key_decisions": ["决策1", "决策2"],
        "risks": ["风险1", "风险2"],
        "follow_ups": ["跟进事项1"],
```

## 六、实战踩坑点

### 坑 1：妙记还在处理中

妙记 API 在处理未完成时返回特定错误码（231001），必须轮询等待。

```python
# 错误处理
if resp.code == 231001:
    # 妙记还在处理中，继续轮询
    await asyncio.sleep(120)
    continue
elif resp.code == 231002:
    # 妙记处理失败
    raise MinutesProcessFailed()
```

### 坑 2：负责人匹配失败

妙记提取的负责人名字可能是**简称/昵称/职位**，与飞书通讯录不匹配。

**应对**：
- 先做精确匹配，失败后做模糊匹配。
- 匹配不上时，任务标记为"未分配"，通知会议主持人人工分配。

### 坑 3：截止时间模糊

妙记可能返回"尽快"、"下周"等模糊时间，无法转成精确日期。

**应对**：
- 模糊日期给一个默认延后（如"下周"→+7 天）。
- 任务创建时附带注释，让负责人自己确认。

### 坑 4：同义任务合并

一场会议可能产生重复的待办（如"通知客户"被提及 3 次）。

**应对**：
- 在创建任务前，对 todo_list 做去重（基于内容相似度）。
- 已存在的任务更新（不创建新的）。

## 七、性能与成本优化

### 优化 1：批量轮询

如果有 10 场会议同时结束，**不要串行轮询**，而是用 Semaphore 控制并发。

```python
async def extract_batch(
    self,
    minute_tokens: List[str],
    max_concurrent: int = 3
) -> Dict[str, MinutesArtifact]:
    """批量提取妙记 AI 产物"""
    semaphore = asyncio.Semaphore(max_concurrent)
    
    async def extract_one(token):
        async with semaphore:
            return (token, await self.extract_with_retry(token))
    
    tasks = [extract_one(t) for t in minute_tokens]
    results = await asyncio.gather(*tasks)
    
    return dict(results)
```

### 优化 2：增量同步

不要每次都重新提取所有会议的妙记。妙记有 `version` 字段，**只提取 version > last_version** 的产物。

### 优化 3：缓存摘要

summary 文本不变时可以缓存，避免重复调用 LLM 分析。

## 八、本章关键 takeaway

- 妙记 AI 产物 API 是飞书生态独占能力（自建应用），准确率 95%+。
- 三类输出：summary、todo_list、sections，结构化程度高。
- 调用限制 5 QPS，处理时间 5-30 分钟，必须**轮询等待**。
- 转换流程：todo_list → 负责人匹配 → 截止时间解析 → 创建任务（含 origin）。
- 实战踩坑：处理中、负责人匹配失败、截止时间模糊、同义任务合并。
- 性能优化：并发轮询、增量同步、缓存。
