# 11 - 签名校验与安全实践

> **TL;DR**：飞书 Webhook 签名校验是**生产安全的最后一道防线**。签名错误 = 任何人都能伪造事件调用你的服务 = 数据被恶意篡改。本篇给出**正确的签名校验实现**（v1 和 v2 两个版本）和安全最佳实践。

---

## 一、为什么签名校验至关重要

如果不校验 Webhook 签名：

- 任何知道 URL 的人都能 POST 任意数据。
- 攻击者可以伪造"任务状态变更为 done" → 你的多维表格被恶意更新。
- 攻击者可以注入恶意数据 → 业务流程被打乱。
- **生产事故** + **数据丢失** + **业务损失**。

飞书的签名机制有 **v1 和 v2 两个版本**，v2 更安全。

---

## 二、飞书签名机制详解

### v1 版本（已逐步废弃）

```
timestamp + nonce + encrypt_key + body
       ↓
HMAC-SHA256
       ↓
Base64 编码
       ↓
X-Lark-Signature header
```

### v2 版本（推荐使用）

```
timestamp + nonce + encrypt_key
       ↓
拼接成 string_to_sign
       ↓
HMAC-SHA256(body, string_to_sign)
       ↓
Base64 编码
       ↓
X-Lark-Signature header
```

### 关键区别

| 维度 | v1 | v2 |
|---|---|---|
| 加密内容 | encrypt_key 直接拼接 | encrypt_key 作为 HMAC key |
| 抗篡改 | 较弱 | 强 |
| 推荐 | 不推荐 | 推荐 |
| 文档清晰度 | 模糊 | 略清晰 |

**注意**：飞书官方文档对签名机制描述有版本混乱，**以官方 SDK 的实现为准**。

## 三、v2 签名校验正确实现

### 核心代码

```python
import hmac
import hashlib
import base64
import time

def verify_lark_webhook_signature_v2(
    timestamp: str,
    nonce: str,
    body: bytes,
    signature: str,
    encrypt_key: str
) -> bool:
    """
    飞书 Webhook 签名校验 v2
    
    Args:
        timestamp: X-Lark-Request-Timestamp header
        nonce: X-Lark-Request-Nonce header
        body: 原始请求体（bytes）
        signature: X-Lark-Signature header
        encrypt_key: 在开发者后台配置的加密 key
    
    Returns:
        bool: 签名是否有效
    """
    # 1. 校验参数完整性
    if not all([timestamp, nonce, signature, encrypt_key]):
        return False
    
    # 2. 校验时间戳（防止重放攻击）
    try:
        ts = int(timestamp)
    except ValueError:
        return False
    
    # 允许 ±5 分钟的时间偏差
    current_ts = int(time.time())
    if abs(current_ts - ts) > 300:
        return False  # 时间戳过期
    
    # 3. 构造 string_to_sign
    string_to_sign = f"{timestamp}{nonce}{encrypt_key}"
    
    # 4. 计算 HMAC-SHA256
    hmac_code = hmac.new(
        string_to_sign.encode("utf-8"),
        body,
        hashlib.sha256
    ).digest()
    
    # 5. Base64 编码
    expected_signature = base64.b64encode(hmac_code).decode("utf-8")
    
    # 6. 常数时间比较（防止时序攻击）
    return hmac.compare_digest(signature, expected_signature)
```

### FastAPI 集成

```python
from fastapi import Request, HTTPException

@app.post("/webhook/feishu")
async def feishu_webhook(request: Request):
    """飞书 Webhook 端点"""
    
    # 1. 提取 headers
    signature = request.headers.get("X-Lark-Signature", "")
    timestamp = request.headers.get("X-Lark-Request-Timestamp", "")
    nonce = request.headers.get("X-Lark-Request-Nonce", "")
    
    # 2. 读取 body（必须先读，后续还要解析）
    body = await request.body()
    
    # 3. 签名校验
    if not verify_lark_webhook_signature_v2(
        timestamp=timestamp,
        nonce=nonce,
        body=body,
        signature=signature,
        encrypt_key=CONFIG.feishu.encrypt_key
    ):
        logger.warning(f"Webhook 签名校验失败: signature={signature[:20]}...")
        raise HTTPException(status_code=401, detail="Invalid signature")
    
    # 4. 解析 payload
    try:
        payload = json.loads(body)
    except json.JSONDecodeError:
        raise HTTPException(status_code=400, detail="Invalid JSON")
    
    # 5. 异步处理（立即返回 200）
    asyncio.create_task(process_event(payload))
    
    return {"code": 0, "msg": "success"}
```

## 四、v1 签名校验（向后兼容）

如果你的应用还在 v1 签名模式：

```python
def verify_lark_webhook_signature_v1(
    timestamp: str,
    nonce: str,
    body: bytes,
    signature: str,
    encrypt_key: str
) -> bool:
    """
    飞书 Webhook 签名校验 v1（已废弃，仅用于兼容）
    """
    # 1. 拼接字符串
    string_to_sign = f"{timestamp}{nonce}{encrypt_key}{body.decode('utf-8')}"
    
    # 2. SHA-256
    digest = hashlib.sha256(string_to_sign.encode("utf-8")).digest()
    
    # 3. Base64
    expected = base64.b64encode(digest).decode("utf-8")
    
    return hmac.compare_digest(signature, expected)
```

### 自动选择版本

```python
def verify_webhook_signature(
    timestamp: str,
    nonce: str,
    body: bytes,
    signature: str,
    encrypt_key: str
) -> bool:
    """自动选择 v1 或 v2"""
    # 尝试 v2
    if verify_lark_webhook_signature_v2(
        timestamp, nonce, body, signature, encrypt_key
    ):
        return True
    
    # v2 失败，尝试 v1（向后兼容）
    return verify_lark_webhook_signature_v1(
        timestamp, nonce, body, signature, encrypt_key
    )
```

## 五、encrypt_key 管理

### 关键原则

- ✅ **不能硬编码**在代码里。
- ✅ **不能提交到 Git 仓库**。
- ✅ **用环境变量或密钥管理服务**。
- ✅ **定期轮换**（每 6-12 个月）。

### 推荐配置

```python
# config.py
import os
from dotenv import load_dotenv

load_dotenv()

# 从环境变量读取
ENCRYPT_KEY = os.environ.get("FEISHU_ENCRYPT_KEY", "")

# 启动时校验
if not ENCRYPT_KEY:
    raise ValueError("FEISHU_ENCRYPT_KEY 未配置")
if len(ENCRYPT_KEY) < 16:
    raise ValueError("FEISHU_ENCRYPT_KEY 太短（至少 16 字符）")
```

### 密钥轮换流程

```python
class EncryptKeyRotator:
    """encrypt_key 轮换管理器"""
    
    def __init__(self):
        # 支持多个 key（过渡期）
        self.keys = [
            os.environ.get("FEISHU_ENCRYPT_KEY_NEW"),
            os.environ.get("FEISHU_ENCRYPT_KEY_OLD"),
            os.environ.get("FEISHU_ENCRYPT_KEY")
        ]
        self.keys = [k for k in self.keys if k]
    
    def verify_with_rotation(self, timestamp, nonce, body, signature) -> bool:
        """用任意一个有效 key 校验"""
        for key in self.keys:
            if verify_lark_webhook_signature_v2(
                timestamp, nonce, body, signature, key
            ):
                return True
        return False
```

**轮换步骤**：
1. 生成新的 encrypt_key。
2. 在飞书开发者后台更新（双重配置：新 key + 旧 key 都接受）。
3. 部署服务支持多 key。
4. 等待 24-48 小时（确保所有重试都用新 key）。
5. 在飞书后台删除旧 key。
6. 服务配置删除旧 key。

### 3. 防重放攻击

```python
class NonceCache:
    """Nonce 缓存（防重放）"""
    
    def __init__(self, redis_client, ttl: int = 600):
        self.redis = redis_client
        self.ttl = ttl  # 10 分钟
    
    async def is_replay(self, nonce: str) -> bool:
        """检查是否重放"""
        key = f"webhook_nonce:{nonce}"
        if await self.redis.exists(key):
            return True
        await self.redis.setex(key, self.ttl, "1")
        return False

nonce_cache = NonceCache(redis_client)

@app.post("/webhook/feishu")
async def feishu_webhook(request: Request):
    nonce = request.headers.get("X-Lark-Request-Nonce", "")
    
    if await nonce_cache.is_replay(nonce):
        logger.warning(f"Webhook 重放: nonce={nonce}")
        raise HTTPException(status_code=401, detail="Replay attack")
    
    ...
```

### 6. Token 安全存储

```python
class SecureTokenStorage:
    """安全 token 存储"""
    
    def __init__(self, redis_client):
        self.redis = redis_client
    
    async def save_token(self, token: str, ttl: int = 7200):
        """存储 token（加密）"""
        # 加密（AES-256）
        encrypted = encrypt_aes256(token, MASTER_KEY)
        await self.redis.setex("feishu:token", ttl, encrypted)
    
    async def get_token(self) -> Optional[str]:
        """读取 token（解密）"""
        encrypted = await self.redis.get("feishu:token")
        if not encrypted:
            return None
        return decrypt_aes256(encrypted, MASTER_KEY)
```

## 七、常见安全错误

### 错误 1：日志中泄露 token

```python
# ❌ 错误
logger.info(f"token: {token}")

# ✅ 正确
logger.info(f"token: {token[:8]}...")
```

### 错误 2：URL 中包含敏感信息

```python
# ❌ 错误：URL 中带 token
webhook_url = f"https://example.com/webhook?token={secret}"

# ✅ 正确：token 在 header 里
headers = {"Authorization": f"Bearer {token}"}
```

### 错误 3：跨域允许任意来源

```python
# ❌ 错误
app.add_middleware(
    CORSMiddleware,
    allow_origins=["*"]  # 任何来源都允许
)

# ✅ 正确
app.add_middleware(
    CORSMiddleware,
    allow_origins=["https://open.feishu.cn"]  # 只允许飞书
)
```

### 错误 4：日志中打印完整 payload

```python
# ❌ 错误：可能包含敏感数据
logger.info(f"Webhook payload: {payload}")

# ✅ 正确：脱敏
def sanitize_payload(payload: Dict) -> Dict:
    """脱敏 payload"""
    sanitized = copy.deepcopy(payload)
    # 移除敏感字段
    if "user" in sanitized:
        sanitized["user"] = {"id": sanitized["user"].get("id")}
    return sanitized

logger.info(f"Webhook payload: {sanitize_payload(payload)}")
```

## 九、实战踩坑

### 坑 1：签名校验实现错误

**症状**：合法的 Webhook 被拒。

**原因**：
- timestamp 单位混淆（毫秒 vs 秒）。
- string_to_sign 拼接顺序错误。
- Body 在解析后被修改（如 `await request.json()` 改变了格式）。

**解决**：
- 严格按官方 SDK 实现。
- 先 `await request.body()` 再 `json.loads(body)`。
- 用官方 SDK 验证一次。

### 坑 2：encrypt_key 泄露

**症状**：服务被攻击。

**原因**：
- 提交到 Git 仓库。
- 日志中打印。
- 客户端代码中暴露。

**解决**：
- 用 `git-secrets` 工具扫描。
- 代码审查时重点检查 secrets。
- 立即轮换已泄露的 key。

### 坑 3：时间戳过期导致失败

**症状**：偶发性签名校验失败。

**原因**：服务端时间不准确，与飞书服务器偏差超过 5 分钟。

**解决**：
- 服务端用 NTP 同步时间。
- 在签名校验中允许更大的时间窗口（如 ±10 分钟）。

## 十、本章关键 takeaway

- 签名校验是生产安全的**最后防线**。
- 飞书签名有 v1 和 v2 两个版本，**推荐 v2**。
- 签名校验正确实现：HMAC-SHA256 + Base64 + 常数时间比较 + 时间戳校验。
- encrypt_key 必须从环境变量读取，**不能硬编码**。
- 定期轮换 encrypt_key 和 app_secret。
- 防重放：用 nonce 缓存（Redis）+ 时间戳校验。
- 速率限制 + 审计日志 + 错误脱敏是必备。
- 所有 secrets 不能进 Git，不能进日志。
