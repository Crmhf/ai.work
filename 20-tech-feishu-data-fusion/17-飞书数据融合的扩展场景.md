# 17 - 飞书数据融合的扩展场景

> **TL;DR**：除了"会议纪要→任务→表格"的标准闭环，**飞书数据融合还能应用于多种业务场景**。本篇讲 5 个扩展场景。

---

## 一、客户成功管理

### 场景

- 客户反馈、客户投诉、客户需求 → 自动归档到多维表格。
- 自动创建跟进任务。
- 进展回写到客户档案。

### 实现

```
客户发送反馈（飞书消息 / 邮件）
    ↓
[反馈识别 Agent] 分类（Bug / 功能请求 / 咨询 / 投诉）
    ↓
自动写入"客户反馈表"
    ↓
自动创建跟进任务
    ↓
[客户成功 Agent] 定期跟进
    ↓
更新"客户档案"（健康度、续约概率）
```

### 数据模型

**客户反馈表**：
- 反馈 ID、内容、客户、来源、类型、严重程度、状态、负责人。
- 关联：客户档案、跟进任务、相关 Bug。

**客户档案表**：
- 客户名、联系人、合同金额、健康度、最近互动、续约概率。

详见：[`05-多维表格数据模型设计.md`](./05-多维表格数据模型设计.md)。

## 二、项目管理增强

### 场景

- 项目进展自动同步（多维表格 → 飞书项目）。
- 任务延期自动告警。
- 项目状态自动可视化（仪表盘）。

### 实现

```
多维表格（项目主表）
    ↓ 实时同步
飞书项目（项目流程）
    ↓ 状态变更
[项目管理 Agent] 检测延期 / 风险
    ↓ 自动告警
飞书消息（项目群）
```

### 关键功能

- **自动延期检测**：截止日期 < 当前日期 && 状态 ≠ "已完成"。
- **风险评估**：基于历史数据预测项目延期概率。
- **自动告警**：飞书消息 / 邮件通知 PM。
- **自动重排**：飞书项目甘特图自动调整依赖。

详见：[`15-飞书项目Projex应用.md`](./15-飞书项目Projex应用.md)。

## 三、销售线索管理

### 场景

- 销售线索（来自展会、广告、网站）→ 自动入库。
- 自动评分（基于客户画像）。
- 自动分配给销售。

### 实现

```
新线索（CRM / 表单 / 飞书消息）
    ↓
[线索识别 Agent] 提取关键信息（公司、需求、预算）
    ↓
[线索评分 Agent] 基于规则 + LLM 评分
    ↓
自动写入"销售线索表"
    ↓
自动分配给对应销售
    ↓
[销售跟进 Agent] 提醒销售跟进
```

### 数据模型

**销售线索表**：
- 线索 ID、公司、联系人、需求、预算、评分、状态、负责人。
- 关联：客户档案、跟进记录、合同。

## 四、人力资源管理

### 场景

- 候选人简历 → 自动入库。
- 自动评估匹配度。
- 自动安排面试。

### 实现

```
候选人投递简历
    ↓
[简历解析 Agent] 提取关键信息
    ↓
[匹配评估 Agent] 评估与岗位匹配度
    ↓
写入"候选人表"
    ↓
自动安排面试（飞书日历）
    ↓
[面试记录 Agent] 自动整理面试反馈
```

### 数据模型

**候选人表**：
- 候选人 ID、姓名、学历、经验、技能、评分、面试反馈、状态。

## 五、财务审批自动化

### 场景

- 报销 / 付款申请 → 自动审核。
- 高风险自动升级人工。
- 状态自动同步。

### 实现

```
员工提交报销（飞书审批）
    ↓
[审核 Agent] 检查合规（金额、类型、附件）
    ↓
低风险：自动通过
中风险：经理审批
高风险：财务总监审批
    ↓
通过 → 自动写入"财务表"
```

### 数据模型

**财务审批表**：
- 申请 ID、申请人、金额、类型、附件、审核结果、审核人。

## 六、扩展场景的设计原则

### 原则 1：从高频刚需场景开始

- 选**每天/每周发生**、**有明显 ROI** 的场景。
- 不要从低频复杂场景开始。

### 原则 2：复用现有闭环

- 基于"会议 → 任务 → 表格"的标准闭环扩展。
- 不要每个场景都重新设计架构。

### 原则 3：HITL 优先

- 任何**金额、删除、对外**操作必须 HITL。
- 不要追求"全自动"。

### 原则 4：可观测性先行

- 每个扩展场景必须有完整 Trace + 日志 + 监控。
- 数据流动必须可追溯。

### 原则 5：渐进式上线

- 先在一个业务线 / 部门试点。
- 验证后再扩展到其他部门。

## 七、场景选择决策树

```
场景是什么？
├── 客户相关 → 客户成功管理
├── 项目相关 → 项目管理增强
├── 销售相关 → 销售线索管理
├── HR 相关 → 人力资源管理
└── 财务相关 → 财务审批自动化

数据源是什么？
├── 飞书消息 → 用妙记 + 消息事件
├── 表单提交 → 用审批 API
└── 外部系统 → 用 API 集成 + Webhook

输出是什么？
├── 创建任务 → 飞书任务 API
├── 更新记录 → 多维表格 API
└── 通知 → 飞书消息 API
```

---

## 八、本章关键 takeaway

- 飞书数据融合可以扩展到**客户成功、项目管理、销售线索、HR、财务**等场景。
- 每个场景都是**标准闭环的变体**（业务事件 → 任务 / 记录 → 表格回写）。
- 设计原则：**高频刚需、复用现有闭环、HITL 优先、可观测先行、渐进上线**。
- 选场景决策：客户 / 项目 / 销售 / HR / 财务 → 不同数据流。
- **不要每个场景都重新设计**，基于已有架构扩展。
