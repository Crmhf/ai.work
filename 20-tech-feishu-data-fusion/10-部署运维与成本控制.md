# 10 - 部署运维与成本控制

> **TL;DR**：飞书数据融合系统的运维核心是 **API 配额管理 + 成本控制 + 稳定性保障**。生产环境的故障 80% 来自配额超限和配置错误。运维清单 + 告警规则 + 应急预案缺一不可。

## 一、飞书 API 配额与限制

### 核心限制

| API | QPS 限制 | 月配额 | 备注 |
|---|---|---|---|
| 妙记 AI 产物 | 5 QPS | 无明确上限 | 受 QPS 限制 |
| 任务 CRUD | 10 QPS | 无明确上限 | 受 QPS 限制 |
| 多维表格 CRUD | 10 QPS | 无明确上限 | 受 QPS 限制 |
| 多维表格 批量 | 10 QPS | 无明确上限 | 写接口同表串行 |
| 会议预约 | 10 QPS | 无明确上限 | 受 QPS 限制 |
| 通讯录 | 5 QPS | 无明确上限 | 受 QPS 限制 |

**关键观察**：飞书 API 主要限制是 QPS，没有月度硬配额。但**应用版本审批后**会有一定限制。

### 配额监控

```python
class QuotaMonitor:
    """API 配额监控"""
    
    def __init__(self):
        self.hourly_calls = defaultdict(int)  # hour_bucket → count
        self.last_alert = {}
    
    def record_call(self, api_name: str):
        hour_bucket = datetime.now().strftime("%Y%m%d%H")
        key = f"{api_name}:{hour_bucket}"
        self.hourly_calls[key] += 1
    
    def check_threshold(self, api_name: str) -> bool:
        """检查是否接近限制（每小时）"""
        hour_bucket = datetime.now().strftime("%Y%m%d%H")
        current = self.hourly_calls.get(f"{api_name}:{hour_bucket}", 0)
        
        # 假设每 QPS 限制 → 每小时上限 = QPS × 3600
        limits = {
            "minutes_artifact": 5,
            "task": 10,
            "bitable": 10
        }
        qps_limit = limits.get(api_name, 10)
        hourly_max = qps_limit * 3600  # 理论最大值
        safe_threshold = hourly_max * 0.8  # 80% 触发告警
        
        if current > safe_threshold:
            # 避免重复告警
            alert_key = f"{api_name}:{hour_bucket}"
            if alert_key not in self.last_alert:
                self.last_alert[alert_key] = True
                return True
        
        return False
```

## 二、性能优化

### 优化 1：批量读写

```python
async def batch_create_records(self, app_token, table_id, records, chunk_size=300):
    """批量创建（分片 300 条/批）"""
    results = {"success": 0, "failed": 0}
    
    for i in range(0, len(records), chunk_size):
        chunk = records[i:i+chunk_size]
        try:
            await self.feishu.batch_create_bitable_records(
                app_token, table_id, chunk
            )
            results["success"] += len(chunk)
        except Exception as e:
            results["failed"] += len(chunk)
            logger.error(f"批次 {i//chunk_size + 1} 失败: {e}")
        
        # 批次间延迟
        await asyncio.sleep(0.15)
    
    return results
```

### 优化 2：缓存

```python
class RedisCache:
    """Redis 缓存封装"""
    
    def __init__(self, redis_client, default_ttl: int = 3600):
        self.redis = redis_client
        self.default_ttl = default_ttl
    
    async def get_or_set(self, key: str, fetch_fn, ttl: int = None):
        """获取或设置缓存"""
        cached = await self.redis.get(key)
        if cached:
            return json.loads(cached)
        
        # 获取并缓存
        value = await fetch_fn()
        await self.redis.setex(key, ttl or self.default_ttl, json.dumps(value))
        return value


# 使用
cache = RedisCache(redis_client)

async def get_user_info(open_id: str):
    return await cache.get_or_set(
        f"user:{open_id}",
        lambda: self.feishu._request("GET", f"/contact/v3/users/{open_id}"),
        ttl=3600
    )
```

### 优化 3：并发控制

```python
class ConcurrencyLimiter:
    """并发限制器（避免对同一表并发写）"""
    
    def __init__(self, max_per_table: int = 1):
        self._locks = defaultdict(asyncio.Lock)
        self.max_per_table = max_per_table
    
    async def with_lock(self, table_id: str, fn):
        """同一 table_id 串行化"""
        async with self._locks[table_id]:
            return await fn()


# 使用
limiter = ConcurrencyLimiter(max_per_table=1)

async def safe_update(table_id, record_id, fields):
    async def _do():
        return await self.feishu.update_bitable_record(
            self.app_token, table_id, record_id, fields
        )
    
    return await limiter.with_lock(table_id, _do)
```

async def reconcile_recent(self, minutes: int = 10):
    """只对账最近 N 分钟的变更"""
    since = int((datetime.now() - timedelta(minutes=minutes)).timestamp() * 1000)
    
    # 1. 拉取多维表格最近变更的记录

## 三、稳定性保障

### 1. 优雅降级

```python
class GracefulDegradation:
    """优雅降级：失败时降级到基础功能"""
    
    async def sync_task_status(self, task_guid: str, status: str):
        """同步任务状态，多级重试"""
        try:
            # 1. 优先：实时同步
            await self.feishu.update_task(task_guid, status)
        except FeishuAPIError as e:
            if e.code in [429, 500, 502, 503, 504]:
                # 限流或服务端错误，进入重试队列
                logger.warning(f"API 异常，进入重试队列: {e}")
                await self.retry_queue.enqueue({
                    "task_guid": task_guid,
                    "status": status,
                    "retry_count": 0
                })
            else:
                # 其他错误，记录但不影响主流程
                logger.error(f"任务同步失败: {e}")
                # 写入失败队列，人工介入
                await self.failed_queue.enqueue({
                    "task_guid": task_guid,
                    "status": status,
                    "error": str(e)
                })
```

### 2. 幂等性

```python
class IdempotencyManager:
    """幂等性管理"""
    
    def __init__(self, redis_client):
        self.redis = redis_client
    
    async def execute_once(self, key: str, fn):
        """同一 key 只执行一次"""
        if await self.redis.exists(key):
            logger.info(f"幂等命中: {key}")
            return
        
        result = await fn()
        await self.redis.setex(key, 3600, "done")
        return result
```

### 3. 熔断器

```python
class CircuitBreaker:
    """熔断器：防止雪崩"""
    
    def __init__(self, failure_threshold: int = 5, recovery_timeout: int = 60):
        self.failure_count = 0
        self.failure_threshold = failure_threshold
        self.recovery_timeout = recovery_timeout
        self.last_failure_time = None
        self.state = "closed"  # closed / open / half-open
    
    async def call(self, fn):
        if self.state == "open":
            if time.time() - self.last_failure_time > self.recovery_timeout:
                self.state = "half-open"
            else:
                raise CircuitOpenError("熔断器开启，跳过调用")
        
        try:
            result = await fn()
            self.failure_count = 0
            self.state = "closed"
            return result
        except Exception as e:
            self.failure_count += 1
            self.last_failure_time = time.time()
            
            if self.failure_count >= self.failure_threshold:
                self.state = "open"
                logger.error(f"熔断器开启: 失败 {self.failure_count} 次")
            
            raise
```

    status = "ok" if all(v == "ok" for v in checks.values()) else "degraded"

## 五、应急预案

### 预案 1：飞书 API 限流

**触发**：告警 `FeishuAPIErrorRateCritical` 或 HTTP 429。

**处理**：
1. 自动开启降级模式：暂停妙记提取（5 QPS 最先达到上限）。
2. 暂停对账任务，避免持续触发限流。
3. 联系飞书技术支持申请临时提升配额。
4. 持续观察 30 分钟后逐步恢复。

### 预案 2：Webhook 完全停止

**触发**：告警 `WebhookStalled`（10 分钟无 Webhook）。

**处理**：
1. 检查 Automation 规则状态（用户可能误关）。
2. 检查 Webhook URL 是否可访问。
3. 检查服务健康状态。
4. 启用应急模式：临时启用高频轮询替代 Webhook。

### 预案 3：妙记 AI 异常

**触发**：妙记 AI 产物持续无法生成（30 分钟超时）。

**处理**：
1. 暂停妙记相关任务。
2. 手动创建兜底任务（不依赖妙记）。
3. 通知会议主持人人工录入待办。

### 预案 4：数据回滚

**触发**：批量更新出错导致数据损坏。

**处理**：
1. 立即停止所有写入操作。
2. 从 Redis 备份恢复最近状态。
3. 用多维表格的"历史记录"功能回滚。
4. 通知相关业务方数据已回滚。
