# 03 - Agent 产品的商业化路径

> **TL;DR**：Agent 产品的商业化有三个核心命题——**定价方式、护城河、PMF 信号**。每个都比传统 SaaS 更难，但天花板也更高。

---

## 一、定价：从 token 到结果的演化

Agent 产品的定价是第一个商业化难题。

### 当前主流：按 token / 按调用次数

这是最简单粗暴的方式，**但它把 AI 价值卖便宜了**。

Agent 调用一次 GPT-4 可能花掉几毛钱（输入 + 输出），用户付的也是几毛。但 Agent 给用户解决的问题可能是节省一小时人工——这单价值远超 token 成本。

结果：用户用得越多，你亏得越多（成本涨得比收入快）。

### 演进方向 1：按席位 / 按任务

类似 SaaS，按月费收。这种适合**稳定、可预期的 Agent 使用场景**（客服 Agent、文档 Agent），用户心理账户是"运营成本"，能接受月费。

### 演进方向 2：按业务结果

按 Agent 实际达成的业务结果收费——比如 CRM Agent 每成功转化一个 lead 收 X 元。

这种最匹配 Agent 的价值，但**度量难、归因难、争议多**。

### 我自己的判断

未来 3 年的主流会从"按 token"过渡到"按席位 / 按任务"，"按业务结果"会出现在**高价值、低争议**的垂直场景。

---

## 二、护城河：算法 vs 工程 vs 数据 vs 场景

Agent 时代，什么才是真正的护城河？

### 误区 1：算法是护城河

LLM 本身是商品（OpenAI / Anthropic / Google / 开源模型都在快速拉齐），**调用同一家模型，你和竞争对手的能力差距接近 0**。

把宝押在"我有更好的模型"上是错的——除非你自研模型，那又是另一个故事。

### 误区 2：Prompt 是护城河

Prompt 是工程产物，不是护城河。任何人都能 copy 你的 prompt，但只有少数人能 copy **配套的工程化能力**（监控、调试、回滚、质量门禁）。

### 真正的护城河候选

**a) 工程化能力**——质量门禁、可观测性、自愈机制、错误恢复。这是 OpenClaw 这种多 Agent 编排框架的核心壁垒。

**b) 数据飞轮**——用户使用 Agent 的反馈数据，反过来优化 Agent 的判断。飞轮越转越厚，护城河越深。

**c) 场景深度**——对特定业务场景的深度理解，能把通用 Agent 调优到远超通用水平的专家级表现。

**d) 集成网络**——Agent 与下游系统（CRM、ERP、表格、IM）的连接关系。一旦你的 Agent 深度接入某个客户的工作流，切换成本会非常高。

我自己的排序：**场景深度 > 集成网络 > 数据飞轮 > 工程化能力 > 算法**。

---

## 三、PMF 信号：怎么算跑通

Agent 产品的 PMF 信号比 SaaS 更难观察，因为：

- 用户留存曲线可能被早期"新鲜感"虚高。
- 任务完成率（Task Completion Rate）这个指标在不同场景差异巨大。
- NPS（净推荐值）在 Agent 早期版本里意义有限（用户对"AI 答非所问"的容忍度 vs "App 闪退"的容忍度不同）。

### 我看重的三个 PMF 信号

**信号 1：用户的"自然复述"** —— 当用户在和同事的对话里说"这个工具帮我做了 XX"，而不是"这个 AI 试一下"，说明产品已经融入工作流。

**信号 2：成本曲线下降而留存曲线持平** —— 说明效率在优化（工程化起作用），不是依赖模型升级。

**信号 3：用户主动要求"接入更多系统"** —— 说明用户已经把 Agent 当成生产工具，而不是玩具。

## 四、三类 Agent 公司的画像

基于商业化逻辑，我把当前 Agent 公司分成三类：

### 类型 A：基础设施型
- **例子**：Anthropic、OpenAI、智谱、月之暗面等模型公司
- **护城河**：算力、数据、模型能力
- **商业风险**：高，资本密集、技术路线风险大

### 类型 B：编排框架型
- **例子**：OpenClaw、LangGraph、AutoGen 等
- **护城河**：开发者社区、工程化能力、协议标准
- **商业风险**：中等，开源压力大

### 类型 C：垂直 Agent 型
- **例子**：法律 Agent、客服 Agent、销售 Agent 等
- **护城河**：场景理解 + 业务集成 + 数据飞轮
- **商业风险**：低天花板，但能稳定盈利

---

## 五、我自己的观察

- **类型 C（垂直 Agent）是最适合独立创业者的赛道**。技术门槛适中、商业逻辑清晰、护城河可见。
- **类型 B（编排框架）的窗口期在缩短**。再过 1-2 年，大厂入场或开源生态成熟，独立公司的机会会变小。
- **类型 A（基础设施）不适合大多数玩家**。需要巨量资本、顶尖人才、长周期耐心。

---

## 六、本文小结

- 定价从 token 演进到席位 / 任务 / 结果，是必然方向。
- 护城河排序：场景深度 > 集成网络 > 数据飞轮 > 工程化能力 > 算法。
- PMF 看"自然复述 + 成本下降 + 主动集成"三个信号。
- 垂直 Agent 是最适合大多数人的赛道。
