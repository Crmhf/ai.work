# 07 - Agent 与 SaaS 的关系

> **TL;DR**：Agent 不会消灭 SaaS，但会重新定义 SaaS 的形态。**未来的产品不是"AI 加进 SaaS"，而是"SaaS 重新长在 AI 上"**。

---

## 一、最常见的误判：Agent 取代 SaaS

每隔一段时间就有声音说"Agent 会取代 SaaS"。这个判断错在**对 SaaS 的本质理解不深**。

SaaS 的本质是什么？不是"网页版的软件"，是：
- **数据集中存储**（业务数据放在云端，多端可访问）。
- **多人协同**（团队共享数据、流程、权限）。
- **流程标准化**（把最佳实践沉淀成产品功能）。
- **订阅制商业**（持续服务 + 持续付费）。

Agent 能取代哪一部分？**只有"流程标准化"和"自动化执行"这一块**。其他三块 Agent 做不了，或者做了没价值。

所以准确的说法是：

> **Agent 不会取代 SaaS，但会重构 SaaS 的"自动化层"**。

---

## 二、SaaS 的三层重构

我把 SaaS 拆成三层，看 Agent 在每层的影响：

### 第一层：数据层（Agent 改变最小）

- **是什么**：数据库、文件存储、数据模型。
- **Agent 的影响**：很小。数据该存还得存，关系型数据库不会被 LLM 取代。
- **变化点**：Agent 是新的"数据生产者"和"数据消费者"。

### 第二层：流程层（Agent 改变最大）

- **是什么**：工作流、审批流、自动化规则、通知。
- **Agent 的影响**：极大。这是 Agent 最擅长的领域。
- **变化点**：从"硬编码的 IFTTT"变成"自然语言描述的 SOP"。

### 第三层：交互层（Agent 改变中等）

- **是什么**：UI、表单、按钮、页面。
- **Agent 的影响**：中等。表单不会消失，但"填空式表单"会被"对话式输入"挤压。
- **变化点**：UI 从"必须品"变成"可选品"，API 成为一等公民。

---

## 三、未来 SaaS 的形态推演

### 形态 1：API-first SaaS

UI 还在，但**所有功能都有 API**。Agent 通过 API 调用 SaaS。

- **典型例子**：Stripe（API 优先）、Linear（API 完整）、Notion（API + 数据库）。
- **Agent 友好度**：高。Agent 直接调用 API 完成任务。
- **商业逻辑**：按调用量计费。

### 形态 2：Agent-embedded SaaS

UI 还在，但**UI 内部嵌入了 Agent 能力**。用户既可以手动操作也可以让 Agent 帮忙。

- **典型例子**：飞书智能伙伴、Notion AI、Salesforce Einstein。
- **Agent 友好度**：中。Agent 能调用部分 API，但完整工作流仍需人工。
- **商业逻辑**：按席位 + 按 AI 调用计费。

### 形态 3：Agent-native SaaS

**没有传统 UI**。Agent 是唯一使用者，人通过"指挥 Agent"完成任务。

- **典型例子**：Devin（编程 Agent）、Clay（销售 Agent）、Harvey（法律 Agent）。
- **Agent 友好度**：极高。专为 Agent 设计。
- **商业逻辑**：按业务结果计费。

## 四、对 SaaS 厂商的建议

如果你正在做 SaaS 产品，我的判断和行动建议：

### 短期（0-12 个月）
- **补齐 API**：所有功能都要有 API，UI 不能是唯一入口。
- **加 Agent 能力**：在 UI 里嵌入 AI 助手，但保持"人类主导"。
- **建立 trace 体系**：记录用户行为和 AI 调用，为后续优化准备数据。

### 中期（1-2 年）
- **重构流程层**：把"硬编码自动化"改成"Agent 自动化"。
- **开放给 Agent 生态**：让你的 SaaS 能被外部 Agent 调用（开放平台 / MCP）。
- **探索按结果计费**：从席位费过渡到"价值分成"。

### 长期（3-5 年）
- **重新设计产品形态**：不再假设"人是唯一使用者"，产品可能同时面向人和 Agent。
- **数据飞轮 + Memory 集成**：让 Agent 记住用户的偏好和历史。
- **可能转型 Agent-native**：如果垂直场景足够清晰，可以考虑做"无 UI"的 Agent-native 版本。

---

## 五、对 Agent 创业者的建议

反过来，如果你正在做 Agent 产品：

### 不要：做"通用 Agent 替代 SaaS"
- "我用 Agent 替代 Salesforce" 这种故事听起来性感，实际上不可能。
- 企业不会因为"AI 替代"就放弃数据集中存储、多人协同、合规审计。

### 要做：做"垂直场景的 Agent 闭环"
- "我用 Agent 帮销售团队自动跟进客户线索" —— 这种可行。
- 关键是**Agent 闭环**：从 lead → 触达 → 跟进 → 转化 → 回写 CRM，全在 Agent 手里。

### 不要：重新发明 SaaS 的轮子
- 别试图做"Agent 版 Excel"。Excel 已经无敌了，做不过。
- 别试图做"Agent 版 Slack"。Slack 的协同护城河你撼动不了。

### 要做：在 SaaS 之上做 Agent 增值
- "我是跑在 Salesforce 之上的销售 Agent"。
- "我是跑在飞书之上的会议 Agent"。
- 这样你的商业模型清晰（给 SaaS 加价值，收费分成），技术路径也清晰（API 集成即可）。

---

## 六、我的判断

- **SaaS + Agent 不会互相取代，会互相融合**。最终形态是"SaaS 提供数据和协同，Agent 提供自动化和决策"。
- **传统 SaaS 厂商最大的风险不是被 Agent 颠覆，是被"用 Agent 重构的新 SaaS"颠覆**。
- **企业不会"用 Agent 替代 SaaS"，会"用 Agent 重构工作流，让 SaaS 的角色从"操作对象"变成"数据源""**。
- **未来 3-5 年最值钱的不是 Agent 产品，是"Agent 友好的 SaaS 平台"**。开放 API、开放数据、开放语义。

---

## 七、本文小结

- SaaS 本质：数据集中 + 多人协同 + 流程标准化 + 订阅制。
- Agent 改变最大的是流程层，UI 改变中等，数据改变最小。
- 三种形态：API-first、Agent-embedded、Agent-native。
- 给 SaaS 厂商的建议：先补 API，再加 AI，最后可能 Agent-native。
- 给 Agent 创业者的建议：垂直闭环，不重新发明 SaaS 轮子，做 SaaS 之上增值。
