# 09 - 可观测性与监控设计

> **TL;DR**：Agent 系统比传统系统更难调试，因为它**不确定、不透明、有状态**。可观测性的三大支柱是 **Metrics（指标）、Logs（日志）、Traces（链路追踪）**。少一个都不行。

---

## 一、为什么 Agent 系统特别需要可观测性

传统软件系统的 bug 来源明确：
- 代码逻辑错误。
- 网络/数据库问题。
- 配置错误。

Agent 系统的 bug 来源**多了一个维度**：
- **模型输出不确定**：同样的 prompt 可能给出不同结果。
- **上下文丢失**：长链路调用中早期信息被遗忘。
- **Agent 状态不可见**：Agent 内部推理过程不透明。
- **契约错位**：Agent 理解任务的方式与 Orchestrator 期望不一致。
- **工具调用失败**：Agent 调用外部 API 出错。

没有可观测性，**出了问题根本不知道是哪一步的哪个 Agent 的哪个判断错了**。

---

## 二、可观测性的三大支柱

### 支柱 1：Metrics（指标）

聚合数据，反映系统整体状态。

#### 关键指标

```yaml
# metrics/monitoring_dashboard.yaml
dashboard:
  name: "Multi-Agent Orchestration Dashboard"
  
  panels:
    # 系统健康
    - title: "System Health"
      metrics:
        - name: "active_projects"
          query: "count(projects{status='RUNNING'})"
        - name: "active_agents"
          query: "count(agents{status='BUSY'})"
        - name: "wave_completion_rate_24h"
          query: "rate(waves_completed[24h]) / rate(waves_started[24h])"
    
    # 任务执行
    - title: "Task Execution"
      metrics:
        - name: "task_success_rate"
          query: "rate(tasks_completed{status='COMPLETED'}[1h]) / rate(tasks_completed[1h])"
        - name: "task_failure_rate"
          query: "rate(tasks_completed{status='FAILED'}[1h]) / rate(tasks_completed[1h])"
        - name: "avg_task_duration_seconds"
          query: "avg(tasks_completed{duration_seconds})"
        - name: "p95_task_duration_seconds"
          query: "quantile(0.95, tasks_completed{duration_seconds})"
    
    # 资源消耗
    - title: "Resource Consumption"
      metrics:
        - name: "tokens_consumed_per_hour"
          query: "rate(tokens_total[1h])"
        - name: "cost_per_hour_usd"
          query: "rate(cost_total[1h])"
        - name: "concurrent_agents"
          query: "max(agents{status='BUSY'})"
    
    # 质量指标
    - title: "Quality Metrics"
      metrics:
        - name: "quality_gate_pass_rate"
          query: "rate(gates_passed[1h]) / rate(gates_evaluated[1h])"
        - name: "auto_heal_success_rate"
          query: "rate(heal_attempts{result='SUCCESS'}[1h]) / rate(heal_attempts[1h])"
        - name: "human_escalation_rate"
          query: "rate(escalations[1h]) / rate(tasks_completed[1h])"
    
    # 异常告警
    - title: "Alerts"
      metrics:
        - name: "tasks_executing_over_30min"
          query: "count(tasks_running{duration_minutes > 30})"
        - name: "agents_in_deadlock"
          query: "count(agents{status='DEADLOCK'})"
        - name: "cost_overrun_projects"
          query: "count(projects{cost_usd > budget_usd})"
```

#### 指标类别

- **业务指标**：任务成功率、用户满意度。
- **性能指标**：任务耗时、波次耗时、并发数。
- **成本指标**：Token 消耗、美元消耗、单位任务成本。
- **质量指标**：门禁通过率、自愈成功率、升级率。

### 支柱 2：Logs（日志）

离散事件记录，反映系统行为细节。

#### 结构化日志格式

```json
{
  "timestamp": "2026-06-21T11:25:30.123Z",
  "level": "INFO",
  "service": "orchestrator",
  "trace_id": "uuid-12345",
  "span_id": "uuid-67890",
  "agent_id": "orchestrator",
  "event": "wave_started",
  "wave_number": 3,
  "tasks_in_wave": ["T2.2", "T2.3", "T2.4", "T3.2"],
  "execution_mode": "parallel",
  "preconditions": ["wave_2_complete"]
}
```

#### 关键事件类型

```yaml
event_types:
  # 调度事件
  - wave_started
  - wave_completed
  - wave_failed
  - task_dispatched
  - task_started
  - task_completed
  - task_failed
  - task_retried
  
  # 质量事件
  - gate_evaluated
  - gate_passed
  - gate_failed
  - heal_attempted
  - heal_succeeded
  - heal_failed
  - human_escalated
  
  # 资源事件
  - agent_started
  - agent_idle
  - agent_deadlock
  - token_consumed
  - cost_threshold_warning
  
  # 通信事件
  - message_sent
  - message_received
  - artifact_created
  - artifact_updated
  
  # 业务事件
  - user_input_received
  - prd_completed
  - deployment_completed
  - user_feedback_received
```

#### 日志采集与查询

- 用 **ELK（Elasticsearch + Logstash + Kibana）** 或 **Loki + Grafana** 存储。
- 按 `trace_id` 索引，可以拉出整个请求链路的所有日志。
- 按 `agent_id` 索引，可以看特定 Agent 的所有行为。

## 四、实时监控实现

### Python 监控示例

```python
# monitoring/project_dashboard.py
import time
from dataclasses import dataclass, field
from typing import Dict, List
from prometheus_client import Counter, Histogram, Gauge

# Prometheus 指标
TASK_COMPLETED = Counter(
    'tasks_completed_total',
    'Total tasks completed',
    ['status', 'agent']
)

TASK_DURATION = Histogram(
    'task_duration_seconds',
    'Task duration in seconds',
    ['agent', 'task_type']
)

TOKENS_CONSUMED = Counter(
    'tokens_total',
    'Total tokens consumed',
    ['model', 'agent']
)

COST_TOTAL = Counter(
    'cost_usd_total',
    'Total cost in USD',
    ['model', 'agent']
)

ACTIVE_AGENTS = Gauge(
    'agents_active',
    'Number of active agents',
    ['agent_type']
)

QUALITY_GATE = Counter(
    'gates_evaluated_total',
    'Quality gates evaluated',
    ['gate_name', 'result']  # result: passed / failed
)

HEAL_ATTEMPTS = Counter(
    'heal_attempts_total',
    'Self-heal attempts',
    ['error_type', 'result']  # result: success / failed
)

HUMAN_ESCALATIONS = Counter(
    'escalations_total',
    'Human escalations',
    ['reason']
)


@dataclass
class AgentMonitor:
    """监控 Agent 执行的工具"""
    
    agent_id: str
    agent_type: str
    
    def __enter__(self):
        ACTIVE_AGENTS.labels(agent_type=self.agent_type).inc()
        self.start_time = time.time()
        return self
    
    def __exit__(self, exc_type, exc_val, exc_tb):
        ACTIVE_AGENTS.labels(agent_type=self.agent_type).dec()
        duration = time.time() - self.start_time
        TASK_DURATION.labels(
            agent=self.agent_id,
            task_type=self.agent_type
        ).observe(duration)
    
    def record_tokens(self, model: str, input_tokens: int, output_tokens: int):
        TOKENS_CONSUMED.labels(model=model, agent=self.agent_id).inc(input_tokens + output_tokens)
        
        # 估算成本（按 GPT-4 价格）
        cost_per_1k = {
            "gpt-4": 0.03,
            "gpt-4-turbo": 0.01,
            "claude-3-opus": 0.015,
            "claude-3-sonnet": 0.003,
        }
        cost = (input_tokens + output_tokens) / 1000 * cost_per_1k.get(model, 0.01)
        COST_TOTAL.labels(model=model, agent=self.agent_id).inc(cost)
    
    def record_gate_result(self, gate_name: str, passed: bool):
        QUALITY_GATE.labels(
            gate_name=gate_name,
            result="passed" if passed else "failed"
        ).inc()
    
    def record_heal(self, error_type: str, success: bool):
        HEAL_ATTEMPTS.labels(
            error_type=error_type,
            result="success" if success else "failed"
        ).inc()
    
    def record_escalation(self, reason: str):
        HUMAN_ESCALATIONS.labels(reason=reason).inc()


# 使用示例
with AgentMonitor(agent_id="T2.2", agent_type="ui_designer") as monitor:
    result = await run_ui_designer_task(task)
    monitor.record_tokens(model="gpt-4", input_tokens=4500, output_tokens=3200)
    monitor.record_gate_result(gate_name="responsive_coverage", passed=True)
```

### Trace 埋点示例

```python
from opentelemetry import trace
from opentelemetry.trace import Status, StatusCode

tracer = trace.get_tracer(__name__)

async def execute_wave(wave: TaskWave):
    with tracer.start_as_current_span(
        f"execute_wave_{wave.number}",
        attributes={
            "wave.number": wave.number,
            "wave.task_count": len(wave.tasks),
            "wave.mode": wave.mode
        }
    ) as span:
        for task in wave.tasks:
            await execute_task_with_trace(task, parent_span=span)

async def execute_task_with_trace(task: Task, parent_span):
    with tracer.start_as_current_span(
        f"task_{task.id}",
        attributes={
            "task.id": task.id,
            "task.agent": task.agent,
            "task.description": task.description
        }
    ) as span:
        try:
            # 调用 Agent
            result = await call_agent(task)
            span.set_attribute("task.outputs", str(result.outputs))
            span.set_attribute("task.tokens.input", result.input_tokens)
            span.set_attribute("task.tokens.output", result.output_tokens)
            span.set_status(Status(StatusCode.OK))
        except Exception as e:
            span.set_status(Status(StatusCode.ERROR, str(e)))
            span.record_exception(e)
            raise
```

## 五、告警与响应

### 告警规则

```yaml
# alerts/alert_rules.yaml
alerts:
  - name: "Task Stuck Over 30min"
    condition: "tasks_running{duration_minutes} > 30"
    severity: "warning"
    action: "notify_oncall"
    message: "任务 {{ task_id }} 运行超过 30 分钟"
  
  - name: "Task Failure Rate > 20%"
    condition: "rate(tasks_failed[10m]) / rate(tasks_completed[10m]) > 0.2"
    severity: "critical"
    action: "page_oncall"
    message: "过去 10 分钟任务失败率超过 20%"
  
  - name: "Cost Overrun"
    condition: "project_cost_usd > project_budget_usd * 0.8"
    severity: "warning"
    action: "notify_owner"
    message: "项目 {{ project_id }} 成本已达预算 80%"
  
  - name: "Agent Deadlock"
    condition: "agents{status='DEADLOCK'} > 0"
    severity: "critical"
    action: "page_oncall"
    message: "{{ count }} 个 Agent 进入死锁状态"
  
  - name: "LLM API Error Rate > 10%"
    condition: "rate(llm_api_errors[5m]) / rate(llm_api_calls[5m]) > 0.1"
    severity: "warning"
    action: "switch_to_fallback_model"
    message: "LLM API 错误率过高，切换到备用模型"
```

### 自动响应

```python
class AlertHandler:
    """告警响应器"""
    
    async def handle(self, alert: Alert):
        if alert.severity == "critical":
            await self._page_oncall(alert)
        
        if alert.action == "switch_to_fallback_model":
            await self._switch_model()
        
        if alert.action == "kill_and_reassign":
            await self._kill_deadlock_agent(alert.context)
        
        # 总是记录
        await self._log_alert(alert)
    
    async def _switch_model(self):
        """切换到备用模型"""
        current = self.openclaw.get_current_model()
        fallback = "claude-3-sonnet" if current == "gpt-4" else "gpt-3.5-turbo"
        self.openclaw.set_default_model(fallback)
        await self.notify(f"已切换到备用模型 {fallback}")
```

## 六、本章关键 takeaway

- 可观测性三大支柱：Metrics（指标）、Logs（日志）、Traces（链路）。
- Agent 系统的不确定性决定可观测性是"必须"，不是"加分项"。
- 关键指标：成功率、耗时、Token 成本、门禁通过率、自愈成功率。
- 日志必须结构化（JSON），按 trace_id 索引。
- Trace 用 OpenTelemetry 标准化，记录完整调用链路。
- 仪表盘分两层：项目级（看单个项目）+ 系统级（看所有项目）。
- 告警必须有分级（warning/critical）和自动响应。
