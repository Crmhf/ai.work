# 11 - 任务分解算法实现

> **TL;DR**：Orchestrator 的核心算法之一是**任务分解**。它把用户模糊需求 → 意图解析 → 模板实例化 → DAG 构建 → 波次划分。本篇给出完整 Python 实现。

## 一、核心数据结构

### Task 数据类

```python
# orchestrator/core/task.py
from dataclasses import dataclass, field
from typing import List, Set, Dict, Optional
from enum import Enum

class TaskStatus(Enum):
    PENDING = "pending"
    READY = "ready"
    RUNNING = "running"
    COMPLETED = "completed"
    FAILED = "failed"
    BLOCKED = "blocked"
    SKIPPED = "skipped"

@dataclass
class Task:
    id: str
    name: str
    agent: str
    description: str
    dependencies: List[str] = field(default_factory=list)
    inputs: List[str] = field(default_factory=list)
    outputs: List[str] = field(default_factory=list)
    estimated_duration_minutes: int = 60
    guardrails: List[str] = field(default_factory=list)
    quality_gates: List[str] = field(default_factory=list)
    
    # 运行时状态（由 Orchestrator 维护）
    status: TaskStatus = TaskStatus.PENDING
    retry_count: int = 0
    max_retries: int = 3
    started_at: Optional[str] = None
    completed_at: Optional[str] = None
    error: Optional[str] = None
    
    # 由 Orchestrator 在构建 DAG 后填充
    downstreams: List[str] = field(default_factory=list)
    
    def to_dict(self) -> Dict:
        return {
            "id": self.id,
            "name": self.name,
            "agent": self.agent,
            "description": self.description,
            "dependencies": self.dependencies,
            "inputs": self.inputs,
            "outputs": self.outputs,
            "estimated_duration_minutes": self.estimated_duration_minutes,
            "status": self.status.value,
            "retry_count": self.retry_count,
            "error": self.error
        }
    
    def __repr__(self):
        return f"Task({self.id}, {self.name}, agent={self.agent}, status={self.status.value})"

## 二、TaskDecomposer 核心类

```python
# orchestrator/skills/task_decomposition.py
from typing import List, Set, Dict, Optional
import yaml
import json

class TaskDecomposer:
    """将用户需求分解为结构化任务 DAG"""
    
    def __init__(self, llm_client, config_path: str = "templates/project_templates.yaml"):
        self.llm = llm_client
        self.templates = self._load_templates(config_path)
    
    def decompose(self, user_requirement: str, project_type: str = "webapp") -> List[Task]:
        """
        主分解入口
        
        1. 识别项目类型与规模
        2. 加载对应模板
        3. 用 LLM 实例化模板（填入具体需求）
        4. 验证依赖图无环
        5. 输出任务列表
        """
        # Step 1: 意图解析
        analysis = self._analyze_intent(user_requirement)
        
        # 检查歧义
        if analysis.get("ambiguity_flags"):
            ambiguity = analysis["ambiguity_flags"]
            if self._is_critical_ambiguity(ambiguity):
                raise AmbiguityError(
                    f"需求存在关键歧义，需用户澄清: {ambiguity}",
                    ambiguity_flags=ambiguity
                )
        
        # Step 2: 模板选择与实例化
        template = self.templates.get(project_type, self.templates["generic"])
        instantiated = self._instantiate_template(template, analysis, user_requirement)
        
        # Step 3: 构建 Task 对象
        tasks = self._build_task_graph(instantiated)
        
        # Step 4: 验证依赖图无环
        if self._has_cycle(tasks):
            cycle = self._find_cycle(tasks)
            raise ValueError(f"生成的任务依赖存在循环: {' -> '.join(cycle)}")
        
        # Step 5: 填充下游
        self._populate_downstreams(tasks)
        
        return tasks
    
    def _analyze_intent(self, requirement: str) -> Dict:
        """使用 LLM 解析用户意图"""
        prompt = f"""
        分析以下用户需求，提取关键信息。
        
        需求: {requirement}
        
        请输出 JSON 格式：
        {{
            "project_type": "webapp|mobile_app|mini_program|api_service",
            "target_platform": ["web", "ios", "android", "wechat_mini"],
            "core_features": ["feature1", "feature2"],
            "user_scale": "small|medium|large",
            "tech_preferences": ["react", "node.js"],
            "constraints": ["budget_limit", "timeline"],
            "ambiguity_flags": ["unclear_auth_flow", "missing_payment_detail"]
        }}
        
        注意：
        - 如果信息不足或模糊，必须在 ambiguity_flags 中标出，不要猜测
        - 项目类型必须从给定选项中选择
        - tech_preferences 是用户的明确偏好，不要自己发挥
        """
        response = self.llm.generate(prompt, format="json")
        return json.loads(response)
    
    def _is_critical_ambiguity(self, flags: List[str]) -> bool:
        """判断歧义是否关键（必须用户澄清）"""
        critical_keywords = [
            "missing_payment", "unclear_auth", 
            "ambiguous_data_model", "no_user_role"
        ]
        return any(keyword in flag.lower() for flag in flags for keyword in critical_keywords)
    
    def _instantiate_template(self, template: Dict, analysis: Dict, requirement: str) -> Dict:
        """用 LLM 将模板中的占位符替换为具体需求"""
        prompt = f"""
        基于以下模板和项目分析，生成具体的任务分解方案。
        
        模板结构:
        {yaml.dump(template, allow_unicode=True)}
        
        项目分析:
        {json.dumps(analysis, ensure_ascii=False, indent=2)}
        
        原始需求:
        {requirement}
        
        要求：
        1. 每个任务必须是可独立执行的（1-4 小时工作量）
        2. 明确每个任务的输入依赖（其他任务的输出路径）
        3. 明确每个任务的输出产物（文件路径或目录路径）
        4. 技术栈选择必须符合用户偏好
        5. 如果分析中有 ambiguity_flags，生成澄清任务而非猜测
        6. 任务粒度要合理：太小（<30分钟）合并，太大（>4小时）拆分
        7. 输出 YAML 格式，包含完整任务列表
        """
        response = self.llm.generate(prompt, format="yaml")
        return yaml.safe_load(response)
    
    def _build_task_graph(self, instantiated: Dict) -> List[Task]:
        """从实例化结果构建 Task 对象列表"""
        tasks = []
        for phase in instantiated.get("phases", []):
            for task_data in phase.get("tasks", []):
                task = Task(
                    id=task_data["id"],
                    name=task_data["name"],
                    agent=task_data["agent"],
                    description=task_data.get("description", task_data["name"]),
                    dependencies=task_data.get("dependencies", []),
                    inputs=task_data.get("inputs", []),
                    outputs=task_data.get("outputs", []),
                    estimated_duration_minutes=task_data.get("estimated_duration_minutes", 60),
                    guardrails=task_data.get("guardrails", []),
                    quality_gates=task_data.get("quality_gates", []),
                    max_retries=task_data.get("max_retries", 3)
                )
                tasks.append(task)
        return tasks
    
    def _populate_downstreams(self, tasks: List[Task]) -> None:
        """填充每个任务的下游任务列表"""
        task_map = {t.id: t for t in tasks}
        for task in tasks:
            for dep_id in task.dependencies:
                if dep_id in task_map:
                    task_map[dep_id].downstreams.append(task.id)
    
    def _has_cycle(self, tasks: List[Task]) -> bool:
        """DFS 检测循环依赖"""
        WHITE, GRAY, BLACK = 0, 1, 2
        color = {t.id: WHITE for t in tasks}
        task_map = {t.id: t for t in tasks}
        
        def dfs(node_id: str) -> bool:
            color[node_id] = GRAY
            for dep_id in task_map[node_id].dependencies:
                if dep_id not in color:
                    continue  # 引用了不存在的任务
                if color[dep_id] == GRAY:
                    return True  # 循环！
                if color[dep_id] == WHITE and dfs(dep_id):
                    return True
            color[node_id] = BLACK
            return False
        
        for task in tasks:
            if color[task.id] == WHITE:
                if dfs(task.id):
                    return True
        return False
    
    def _find_cycle(self, tasks: List[Task]) -> List[str]:
        """找到循环依赖的路径"""
        WHITE, GRAY, BLACK = 0, 1, 2
        color = {t.id: WHITE for t in tasks}
        task_map = {t.id: t for t in tasks}
        parent = {t.id: None for t in tasks}
        
        def dfs(node_id: str) -> Optional[List[str]]:
            color[node_id] = GRAY
            for dep_id in task_map[node_id].dependencies:
                if dep_id not in color:
                    continue
                if color[dep_id] == GRAY:
                    # 找到循环，构建路径
                    cycle = [dep_id, node_id]
                    p = parent[node_id]
                    while p is not None and p != dep_id:
                        cycle.append(p)
                        p = parent[p]
                    cycle.append(dep_id)
                    return list(reversed(cycle))
                if color[dep_id] == WHITE:
                    parent[dep_id] = node_id
                    result = dfs(dep_id)
                    if result:
                        return result
            color[node_id] = BLACK
            return None
        
        for task in tasks:
            if color[task.id] == WHITE:
                parent[task.id] = None
                result = dfs(task.id)
                if result:
                    return result
        return []
    
    def _load_templates(self, config_path: str) -> Dict:
        """加载项目模板"""
        with open(config_path) as f:
            return yaml.safe_load(f)
```

## 三、波次划分算法

```python
def build_execution_waves(tasks: List[Task]) -> List[List[Task]]:
    """
    将任务按依赖关系分组，同层任务可并行。
    返回的每个内层列表是一个"波次"。
    
    算法：拓扑排序 + 入度递减
    """
    in_degree = {t.id: len(t.dependencies) for t in tasks}
    task_map = {t.id: t for t in tasks}
    waves = []
    remaining = set(t.id for t in tasks)
    
    while remaining:
        # 当前所有入度为 0 的任务（无未满足依赖）
        current_wave_ids = [
            tid for tid in remaining 
            if in_degree.get(tid, 0) == 0
        ]
        
        if not current_wave_ids:
            # 没有可执行的任务，要么完成要么循环
            cycle = find_cycle_in_remaining(task_map, remaining)
            raise ValueError(f"依赖循环 detected: {' -> '.join(cycle)}")
        
        # 构建当前波次
        current_wave = [task_map[tid] for tid in current_wave_ids]
        waves.append(current_wave)
        
        # 标记这些任务已加入波次
        remaining -= set(current_wave_ids)
        
        # 减少下游任务的入度
        for tid in current_wave_ids:
            task = task_map[tid]
            for downstream_id in task.downstreams:
                if downstream_id in in_degree:
                    in_degree[downstream_id] -= 1
    
    return waves

class DecompositionError(Exception):
    """任务分解基础异常"""
    pass

class AmbiguityError(DecompositionError):
    """需求歧义异常"""
    def __init__(self, message: str, ambiguity_flags: List[str]):
        super().__init__(message)
        self.ambiguity_flags = ambiguity_flags

class CycleError(DecompositionError):
    """循环依赖异常"""
    def __init__(self, message: str, cycle_path: List[str]):
        super().__init__(message)
        self.cycle_path = cycle_path

class TemplateNotFoundError(DecompositionError):

## 六、LLM 客户端抽象

```python
# orchestrator/core/llm_client.py
from abc import ABC, abstractmethod
from typing import Optional

class LLMClient(ABC):
    """LLM 客户端抽象基类"""
    
    @abstractmethod
    def generate(self, prompt: str, format: str = "text", **kwargs) -> str:
        """调用 LLM 生成内容"""
        pass

class OpenAIClient(LLMClient):
    """OpenAI 实现"""
    def __init__(self, api_key: str, model: str = "gpt-4"):
        import openai
        self.client = openai.OpenAI(api_key=api_key)
        self.model = model
    
    def generate(self, prompt: str, format: str = "text", **kwargs) -> str:
        response = self.client.chat.completions.create(
            model=self.model,
            messages=[{"role": "user", "content": prompt}],
            temperature=kwargs.get("temperature", 0.3),
            max_tokens=kwargs.get("max_tokens", 4000)
        )
        content = response.choices[0].message.content
        
        if format == "json":
            return self._extract_json(content)
        elif format == "yaml":
            return self._extract_yaml(content)
        return content
    
    def _extract_json(self, content: str) -> str:
        """从 LLM 输出中提取 JSON"""
        # LLM 可能返回 ```json ... ``` 包裹的内容
        if "```json" in content:
            start = content.find("```json") + 7
            end = content.find("```", start)
            return content[start:end].strip()
        return content
    
    def _extract_yaml(self, content: str) -> str:
        """从 LLM 输出中提取 YAML"""
        if "```yaml" in content:
            start = content.find("```yaml") + 7
            end = content.find("```", start)
            return content[start:end].strip()
        return content

class AnthropicClient(LLMClient):
    """Anthropic 实现"""
    def __init__(self, api_key: str, model: str = "claude-3-opus"):
        import anthropic
        self.client = anthropic.Anthropic(api_key=api_key)
        self.model = model
    
    def generate(self, prompt: str, format: str = "text", **kwargs) -> str:
        response = self.client.messages.create(
            model=self.model,
            max_tokens=kwargs.get("max_tokens", 4000),
            messages=[{"role": "user", "content": prompt}]
        )
        content = response.content[0].text
        if format == "json":
            return self._extract_json(content)
        elif format == "yaml":
            return self._extract_yaml(content)
        return content
    
    def _extract_json(self, content: str) -> str:
        # 同 OpenAI
        pass
    
    def _extract_yaml(self, content: str) -> str:
        # 同 OpenAI
        pass

import asyncio
from orchestrator.skills.task_decomposition import TaskDecomposer
from orchestrator.core.llm_client import OpenAIClient

async def main():
    # 初始化 LLM 客户端
    llm = OpenAIClient(api_key="sk-...", model="gpt-4")
    
    # 创建分解器
    decomposer = TaskDecomposer(llm)
    
    # 分解用户需求
    requirement = "做一个电商小程序，包含商品展示、购物车、下单支付功能"

        tasks = decomposer.decompose(requirement, project_type="mini_program")

    waves = build_execution_waves(tasks)
    
    print(f"\n分为 {len(waves)} 个执行波次:")
    for i, wave in enumerate(waves):
        print(f"  Wave {i+1}: {[t.id for t in wave]}")

## 八、算法复杂度分析

### 时间复杂度

- 意图解析：O(LLM 调用)
- 模板实例化：O(LLM 调用)
- DAG 构建（含循环检测）：O(V + E)，V = 任务数，E = 依赖数
- 波次划分：O(V + E)
- **总计**：主要瓶颈是 LLM 调用，算法部分是 O(V + E)

### 空间复杂度

- 任务存储：O(V)
- DAG 邻接表：O(V + E)
- 波次结果：O(V)
- **总计**：O(V + E)

### 优化方向

- LLM 调用是主要瓶颈，**可以用缓存**（相同 intent 用相同结果）。
- 模板可以预编译（不每次都让 LLM 解析）。
- 大型项目（V > 1000）可以分层分解（先按阶段分，再按任务分）。

## 九、实战踩坑点

### 坑 1：模板过度依赖 LLM

模板应该**结构化**（YAML），LLM 只负责"填值"。不要让 LLM 自己决定任务结构。

### 坑 2：循环检测缺失

LLM 生成的依赖可能出错（如 "T2.1 依赖 T1.1，T1.1 依赖 T2.1"）。必须做循环检测。

### 坑 3：歧义不追问

LLM 会"猜测"而不是"追问"。必须在 prompt 中强制要求"歧义必须输出 ambiguity_flags"。

### 坑 4：任务粒度不均

有些任务太大（编码整个后端），有些太小（更新一行代码）。需要在 prompt 中明确粒度要求（1-4 小时）。

---

## 十、本章关键 takeaway

- 任务分解 5 步：意图解析 → 模板选择 → 实例化 → DAG 构建 → 波次划分。
- 核心数据结构：Task（含 status、retry_count、dependencies、downstreams）。
- 关键算法：DFS 检环、拓扑排序波次划分。
- 模板是骨架（YAML），LLM 只填值。
- 歧义必须显式追问，不能让 LLM 猜测。
- 必须做循环检测 + 粒度校验。
- LLM 调用是性能瓶颈，用缓存优化。
