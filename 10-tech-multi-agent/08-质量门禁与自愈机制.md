# 08 - 质量门禁与自愈机制

> **TL;DR**：质量门禁是多 Agent 系统能跑 7×24 的关键。每个阶段都有"可机器验证的"通过标准，不通过则自动回溯修复（最多 3 轮）。3 轮还不通过，升级到人类。

---

## 一、为什么质量门禁是"生产可用"的关键

Agent 必然会犯错：
- LLM 输出幻觉。
- 上下文超载导致判断错位。
- 契约理解错误。
- 工具调用失败。

没有质量门禁的系统：
- 错的任务往下游传，下游 Agent 基于错误产物继续 → 错误扩散。
- 测试 Agent 跑了但发现 bug 也"放过" → 生产事故。
- 人工事后发现 → 修复成本 10x 上升。

**质量门禁 = 在错误扩散前拦截**。

---

## 二、质量门禁的核心设计

### 原则 1：可机器验证

每个门禁规则必须是**机器可执行的检查**，不是"看起来不错"。

```yaml
# ✅ 好的门禁（可验证）
- "file_exists('shared/01_PRD/PRD.md')"
- "word_count('shared/01_PRD/PRD.md') > 500"
- "lint_score > 80"
- "test_coverage > 80"

# ❌ 不好的门禁（主观）
- "PRD 看起来完整"
- "代码风格不错"
```

### 原则 2：可量化

每个门禁都有明确阈值：

```yaml
# ✅ 明确阈值
- "test_coverage > 80"
- "lint_score > 80"
- "no_critical_security_issues()"
- "all_required_sections_present(['Overview', 'User Stories', 'Acceptance Criteria'])"
```

### 原则 3：分层

门禁按阶段分层：
- **Phase 1（PRD）门禁**：文件存在、字数、必含章节。
- **Phase 2（UI）门禁**：设计系统定义、覆盖所有页面。
- **Phase 3（架构）门禁**：API Spec 是 OpenAPI 3.0、Schema 有索引。
- **Phase 4（实现）门禁**：lint、test coverage、安全扫描。
- **Phase 5（测试）门禁**：所有 acceptance criteria 通过、critical bug = 0。
- **Phase 6（部署）门禁**：Docker 镜像构建成功、健康检查通过。

## 四、质量门禁的实现

### GateChecker 核心

```python
# orchestrator/quality/gate_checker.py
from typing import Dict, List
import subprocess

class GateChecker:
    """质量门禁检查器"""
    
    def __init__(self, gates_config_path: str):
        self.gates = self._load_gates(gates_config_path)
    
    def check(self, task_id: str, artifacts: List[str]) -> GateResult:
        """对指定任务的产出执行所有适用的门禁"""
        applicable_gates = [g for g in self.gates if task_id in g["applies_to"]]
        
        results = []
        for gate in applicable_gates:
            result = self._evaluate_gate(gate, artifacts)
            results.append(result)
        
        all_passed = all(r.passed for r in results)
        return GateResult(
            task_id=task_id,
            passed=all_passed,
            gate_results=results
        )
    
    def _evaluate_gate(self, gate: Dict, artifacts: List[str]) -> SingleGateResult:
        """评估单个门禁"""
        # 编译 condition 表达式为可执行函数
        condition_fn = self._compile_condition(gate["condition"])
        
        try:
            passed = condition_fn(artifacts)
            return SingleGateResult(
                name=gate["name"],
                passed=passed,
                error=None if passed else "条件不满足"
            )
        except Exception as e:
            return SingleGateResult(
                name=gate["name"],
                passed=False,
                error=f"检查异常: {str(e)}"
            )
    
    def _compile_condition(self, condition: str):
        """编译条件表达式为可执行函数"""
        # 使用 AST 解析 + 安全沙箱执行
        # 或使用特定的 DSL（避免直接 eval）
        return ConditionCompiler.compile(condition)
```

## 五、自愈机制（Self-healing）

当门禁失败时，系统自动尝试修复。

### 修复流程

```
门禁失败
    │
    ▼
[Step 1] 错误分类
    │
    ├─ 产物格式错误（缺字段、格式错）→ 重新格式化
    │
    ├─ 内容缺失（字数不够、章节不全）→ 让 Agent 补充内容
    │
    ├─ 逻辑错误（与契约不符）→ 让 Agent 重做
    │
    └─ 系统错误（Agent 卡死、工具失败）→ 重试
    │
    ▼
[Step 2] 重试（最多 N 次）
    │
    ▼
[Step 3] 升级人工（重试超过阈值）
```

### 自愈策略配置

```yaml
# self_healing.yaml
healing_strategies:
  - error_type: "missing_artifact"
    detection: "file_not_exists(expected_path)"
    action: "reassign_to_owner_with_explicit_requirement"
    max_retries: 2
    retry_prompt_template: |
      上次你的产出缺少文件 {{ expected_path }}。
      请明确写出该文件，包含以下内容：{{ required_content }}。
  
  - error_type: "format_error"
    detection: "schema_validation_failed"
    action: "reformat_and_validate"
    max_retries: 2
    retry_prompt_template: |
      上次你的产出不符合 schema：
      {{ validation_errors }}
      请严格按照以下 schema 输出：{{ schema }}
  
  - error_type: "content_insufficient"
    detection: "word_count_below_threshold"
    action: "request_expansion"
    max_retries: 2
    retry_prompt_template: |
      上次你的产出字数 {{ actual_count }} 低于阈值 {{ threshold }}。
      请扩充以下内容：{{ topics_to_expand }}
  
  - error_type: "logical_error"
    detection: "logic_check_failed"
    action: "request_redo"
    max_retries: 3
    retry_prompt_template: |
      上次你的产出有以下逻辑错误：{{ logic_errors }}
      请重新完成，特别注意：{{ key_points }}
  
  - error_type: "agent_timeout"
    detection: "execution_time > threshold"
    action: "retry_with_different_model"
    max_retries: 2
    retry_prompt_template: |
      上次任务超时。可能任务太复杂，请按以下方式简化：
      1. 拆成多个小任务
      2. 减少单步复杂度
  
  - error_type: "agent_deadlock"
    detection: "agent_stuck_in_loop"
    action: "kill_and_reassign"
    max_retries: 1
    retry_prompt_template: |
      之前的 Agent 在以下循环中卡死：{{ stuck_loop }}
      请换一种思路完成：{{ alternative_approach }}
```

### 自愈执行

```python
class SelfHealer:
    """自愈机制执行器"""
    
    def __init__(self, strategies_path: str, openclaw_client):
        self.strategies = self._load_strategies(strategies_path)
        self.openclaw = openclaw_client
    
    async def heal(self, task: Task, gate_result: GateResult) -> HealResult:
        """尝试修复门禁失败"""
        for gate in gate_result.failed_gates:
            error_type = self._classify_error(gate)
            strategy = self.strategies.get(error_type)
            
            if not strategy:
                continue
            
            if task.retry_count >= strategy["max_retries"]:
                # 超过重试次数，升级人工
                return await self._escalate_to_human(task, gate)
            
            # 重试
            task.retry_count += 1
            retry_prompt = strategy["retry_prompt_template"].format(
                **self._extract_context(task, gate)
            )
            
            result = await self.openclaw.call_agent(
                agent_id=task.agent,
                message={
                    "type": "TASK_RETRY",
                    "task_id": task.id,
                    "retry_prompt": retry_prompt,
                    "previous_error": gate.error
                }
            )
            
            # 重新检查门禁
            new_gate_result = self.gate_checker.check(task.id, result.artifacts)
            if new_gate_result.passed:
                return HealResult(success=True, task=task, result=result)
        
        # 仍然失败，升级
        return await self._escalate_to_human(task, gate_result)
    
    def _classify_error(self, gate: SingleGateResult) -> str:
        """分类错误类型"""
        if "file not found" in gate.error.lower():
            return "missing_artifact"
        if "schema" in gate.error.lower():
            return "format_error"
        if "word count" in gate.error.lower():
            return "content_insufficient"
        if "logic" in gate.error.lower():
            return "logical_error"
        if "timeout" in gate.error.lower():
            return "agent_timeout"
        if "loop" in gate.error.lower():
            return "agent_deadlock"
        return "unknown_error"
    
    async def _escalate_to_human(self, task: Task, gate_result: GateResult):
        """升级到人工处理"""
        return await self.openclaw.send_to_human(
            message={
                "type": "ESCALATION",
                "task_id": task.id,
                "agent": task.agent,
                "retry_count": task.retry_count,
                "gate_failures": [g.to_dict() for g in gate_result.failed_gates],
                "context": task.description,
                "suggested_action": "请人工审查并提供修正方案"
            }
        )
```

## 六、迭代控制（Feedback Loop）

测试 Agent 发现 Bug 时触发修复循环：

```
编码 Agent 提交代码
    │
    ▼
QA Agent 执行测试
    │
    ├─ 通过 → 进入下一阶段
    │
    └─ 失败 → 生成 BugReport.md
              │
              ▼
        Orchestrator 分析 Bug 归属
              │
              ├─ 代码逻辑错误 → 分配回编码 Agent 修复
              │
              ├─ 设计缺陷 → 分配回架构/UI Agent 修改设计
              │
              └─ 需求理解偏差 → 分配回产品 Agent 澄清需求
              │
              ▼
        修复后重新进入 QA 验证
        （最多 3 轮迭代，超过则人工介入）
```

### 关键设计

1. **Bug 归属分析**：QA 报告 Bug 时附带"可能的根因"（基于 bug 描述、相关文件、契约对比）。
2. **修复路由**：根据归属自动路由到对应 Agent。
3. **修复上下文**：把 Bug 报告、相关代码、相关契约一并给修复 Agent。
4. **迭代上限**：最多 3 轮，避免无限循环。
5. **自动升级**：3 轮后自动升级人工，把所有上下文打包。

## 七、我的实战经验

### 经验 1：门禁越早越好

不要等所有阶段完成才检查。在每个 wave 完成时立即检查门禁，错误越早发现修复成本越低。

### 经验 2：门禁规则要"渐进严格"

```
v1：基础检查（文件存在、字数、章节）
v2：内容检查（schema 验证、覆盖率）
v3：质量检查（lint、test、安全扫描）
```

早期跑 v1，跑稳了再加 v2、v3。不要一上来就最严格。

### 经验 3：自愈 prompt 要"具体"

不要写"请修复错误"。要写"上次你的产出缺少文件 X，请明确写出该文件，包含以下内容：Y、Z"。

### 经验 4：升级不是失败

升级人工不是"系统失败"，是"系统正确地识别出无法自动修复"。要给人工完整的上下文，否则人工无法快速介入。

### 经验 5：门禁与质量分离

门禁是"通过/不通过"的硬规则。质量评估是"主观打分"的软指标（如设计美观度）。两者分开。

## 八、本章关键 takeaway

- 质量门禁是 7×24 运行的关键：错误在扩散前拦截。
- 三大原则：可机器验证、可量化、分层。
- 门禁配置用 YAML 描述，每个阶段有不同检查项。
- 自愈机制按错误分类，每类有对应的重试 prompt 模板。
- 最多重试 3 次，超过则升级人工。
- Bug 修复循环：测试 → 归属分析 → 路由到对应 Agent → 修复 → 重测。
- 门禁渐进严格，避免一上来过严。
