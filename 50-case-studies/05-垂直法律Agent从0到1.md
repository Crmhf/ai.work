# 05 - 垂直法律 Agent 从 0 到 1

> **TL;DR**：一个**垂直法律 Agent** 从概念到产品 6 个月，月收入从 0 到 $30k。本篇是创业视角的完整路径：选场景、找 PMF、构建 MVP、迭代到 PMF、规模化。

---

## 一、机会识别

### 背景

2025 年中，我观察到几个趋势：

- 大量中小企业有"合同审查"需求，但请不起律师（$200-500/小时）。
- 现有 SaaS（CLM 系统）太复杂，需要专门培训。
- LLM 能力提升，使"AI 辅助合同审查"成为可能。

### 假设

> **垂直法律 Agent = "中小企业友好的合同审查助手"**。

- 输入：合同文档（PDF / Word）。
- 输出：风险点、修改建议、相关法规引用。
- 价值：$50/份（vs 律师 $500/份）。

---

## 二、MVP 验证（第 1-2 个月）

### 目标

验证"中小企业愿意为 AI 合同审查付费"。

### 方案

- 最小可行产品：单 Agent + GPT-4 + 简单 prompt。
- 处理 1 类合同（NDA、保密协议）。
- 手动审查 AI 输出（保证质量）。
- 找 10 个朋友/前同事试用，收集反馈。

### 结果

- 10 个试用，8 个愿意付费。
- 关键反馈：**准确率是核心**（不能出错）+ **速度是加分项**（比律师快）。
- 定价测试：$50/份 → **8/10 接受**。

### 决策

✅ **PMF 验证**——继续。

---

## 三、MVP 构建（第 3-4 个月）

### 产品功能

- **核心**：合同上传 → AI 分析 → 风险报告。
- **附加**：人工律师复核（增值服务，$200/份）。

### 技术架构

```
用户上传合同（PDF/Word）
    ↓
[文档解析] 转纯文本
    ↓
[RAG] 检索相关法规、案例
    ↓
[风险识别 Agent] GPT-4 + 提示词工程
    ↓
[质量验证 Agent] 检查答案一致性
    ↓
[律师复核]（可选）人工审核
    ↓
[报告生成] PDF 报告
```

### 关键决策

- **不追求全自动**：高风险操作必须人工律师复核。
- **从 NDA 单一类型起步**：避免泛化导致准确率下降。
- **律师合作为护城河**：AI 给出建议，律师签字背书。

### 早期客户

- 第 4 个月末：20 个付费客户。
- 月收入：$1,000。
- 客户类型：初创公司、小微企业。

---

## 四、产品迭代（第 5-6 个月）

### 关键改进

#### 1. 准确率提升

- 加入**双 Agent 验证**（一个分析、一个复核）。
- 持续收集失败案例，迭代 prompt。
- 准确率从 75% 提升到 92%。

#### 2. 支持更多合同类型

- 服务协议、租赁合同、采购合同。
- 每个类型有专门的 prompt 模板。

#### 3. 客户体验

- 在线编辑器（AI 建议直接在合同上标注）。
- 历史记录（多次审查对比）。
- 团队协作（多人 review）。

#### 4. 营销

- 内容营销（"AI 合同审查"博客）。
- 律师社群推广。
- 与企业服务商合作（HR SaaS、CRM 厂商）。

### 结果

- 第 6 个月末：120 个付费客户。
- 月收入：$6,000（年化 $72,000）。
- 续费率：85%。
- 客户满意度（NPS）：72。

---

## 五、规模化（第 7-12 个月）

### 关键动作

#### 1. 引入更多律师网络

- 签约 50+ 合作律师（按审查费分成）。
- 律师可以接"AI 复核订单"作为副业。

#### 2. 企业版

- 多用户、权限管理、审计日志。
- SSO 集成。
- 私有化部署选项。

#### 3. API 开放

- 开放 API 给企业用户嵌入自己的系统。
- 按调用量收费。

#### 4. 多模态

- 支持音频合同（电话录音转合同）。

### 结果

- 第 12 个月末：500 个付费客户 + 30 个企业客户。
- 月收入：$30,000（年化 $360,000）。
- 团队：10 人（5 个工程师 + 3 个律师运营 + 2 个销售）。

---

## 六、关键决策回顾

### 决策 1：垂直 vs 通用

**选择**：垂直（法律 > 合同审查）。

**原因**：
- 通用法律 Agent 准确率不够（法律容错率低）。
- 垂直场景 ROI 清晰（中小企业愿意为节省的律师费买单）。
- 律师合作为护城河（AI + 律师 = 信任）。

### 决策 2：AI 全自动 vs AI + 律师

**选择**：AI + 律师（混合模式）。

**原因**：
- 法律容错率低，全自动风险高。
- 律师合作为合规背书，增加客户信任。
- AI 处理标准化部分，律师处理复杂部分，效率最高。

### 决策 3：自建 vs 用 LangChain 等框架

**选择**：部分自建 + 部分用 LangChain。

**原因**：
- 核心算法（合同分析）自建。
- 基础设施（RAG、prompt 管理）用 LangChain。
- 平衡开发效率和灵活性。

### 决策 4：B2B vs B2C

**选择**：B2B（中小企业 + 大企业）。

**原因**：
- C 端合同审查需求不频繁（用户买一次就不用了）。
- B 端持续付费（每月多次合同）。
- B 端客单价高（LTV 高）。

---

## 七、护城河分析

### 1. 数据飞轮

- 每次审查 = 新的训练数据。
- 数据越多，AI 越准。
- 越准，客户越多 → 数据更多。

### 2. 律师网络

- 50+ 合作律师是稀缺资源。
- 律师网络一旦建立，难以复制。

### 3. 行业知识

- 合同模板、行业惯例、法规更新 → 持续投入。
- 新进入者需要时间积累。

### 4. 客户信任

- 长期客户关系 + 复购 + 转介绍。
- 法律是"信任"生意。

---

## 八、关键教训

### 教训 1：先验证 PMF，再建产品

MVP 验证 2 个月，没花多少钱，但**确认了 PMF**。

### 教训 2：垂直 > 通用

垂直场景 ROI 清晰、护城河可见、规模化路径明确。

### 教训 3：AI + 人工 > 纯 AI

法律、医疗等高容错率场景，**AI 是工具，人是责任主体**。

### 教训 4：律师网络是护城河

技术可以被复制，**律师网络是稀缺资源**。

### 教训 5：客户成功 > 销售

合同审查的复购率比获客更重要。**让客户成功比拉新客户重要**。

---

## 九、给创业者的建议

### 1. 选垂直场景

- 场景简单、ROI 明确。
- 高频、可重复。
- 容错率可控。

### 2. 找到付费意愿

- 用 MVP 验证**5-10 个真实用户**愿意付费。
- 验证后再投入工程。

### 3. AI + 人工混合

- 高容错率场景，纯 AI 风险大。
- AI 处理标准化，人处理复杂。

### 4. 持续迭代

- Agent 项目是"持续迭代"，不是"一次交付"。
- 每周小迭代，月度大迭代。

### 5. 数据飞轮

- 设计让数据"自然积累"的机制。
- 数据飞轮 = 长期护城河。

---

## 十、本章关键 takeaway

- 垂直法律 Agent 从 0 到 1 用 6 个月，月收入 $0 → $30k。
- 关键决策：垂直法律、AI + 律师混合、B2B、自建核心算法。
- 护城河：数据飞轮 + 律师网络 + 行业知识 + 客户信任。
- 核心经验：**MVP 验证 PMF → 持续迭代 → 规模化**。
- 教训：**先验证 PMF 再建产品、AI + 人工混合、数据飞轮是护城河**。
