# 04 - 失败案例：为什么我的第一个 Agent 项目失败了

> **TL;DR**：我做的第一个 Agent 项目**上线 2 个月后下线**。本篇诚实复盘所有错误，希望你避开同样的坑。

---

## 一、项目概况

### 项目

"AI 项目助理"—— 一个自动帮 PM 跟踪项目进度的 Agent。

### 目标

- 自动汇总多项目进度（从多个系统拉数据）。
- 自动识别延期风险（基于历史数据）。
- 自动给 PM 发提醒。

### 时间

- 第 1-2 个月：开发。
- 第 3 个月：上线（仅自己用）。
- 第 4-5 个月：推广失败。
- 第 6 个月：下线。

---

## 二、失败的 8 个错误

### 错误 1：把 Agent 当 "更聪明的 ChatGPT"

**现象**：我只用了 prompt，没有 RAG、没有 Tool-use、没有 Memory。

**结果**：LLM 没有真实数据，只能"凭空生成"。所有"项目进度"都是编造的。

**应该**：从一开始就用 RAG + Tool-use，让 Agent 真正访问数据。

### 错误 2：没有质量门禁

**现象**：Agent 输出什么就用什么，没校验。

**结果**：LLM 编造的"风险预警"经常发生，PM 看多了就免疫了。

**应该**：每个 Agent 输出都有 schema 校验 + 置信度评估。

### 错误 3：没有可观测性

**现象**：Agent 出错时，我不知道哪里出错、为什么出错。

**结果**：debug 一周都没定位问题，最后放弃。

**应该**：从第一天起，所有 LLM 调用都有 trace + log。

### 错误 4：过度追求"全自动"

**现象**：我想让 Agent 自动运行，不需要人工。

**结果**：第一次出错后，PM 完全不信任 Agent，停止使用。

**应该**：**HITL 优先**，先建立信任，再逐步自动化。

### 错误 5：没有收集用户反馈

**现象**：Agent 输出后，没有让用户反馈"对/错"。

**结果**：我不知道 Agent 实际效果如何，无法改进。

**应该**：每个输出都有反馈按钮，自动收集失败案例。

### 错误 6：成本失控

**现象**：每天 50 个项目查询 × 每次 $0.03 = $1.5/天 = $45/月。

但实际因为 Agent 重试、死循环，实际成本是 $200/月。

**应该**：**预算 + 告警 + max_iterations** 必须有。

### 错误 7：选错场景

**现象**：我选了"项目进度跟踪"作为第一个 Agent 场景。

**为什么错**：
- 项目进度数据分散在多个系统（Git、Jira、飞书任务），集成复杂。
- PM 对 Agent 不信任（怕"AI 抢饭碗"）。
- ROI 不清晰（节省的时间难量化）。

**应该**：选**简单、高频、ROI 明确**的场景（如 FAQ 自动化）。

### 错误 8：一个人做所有事

**现象**：我一个人写 prompt、写代码、运维、推广、收集反馈。

**结果**：分身乏术，最后什么都没做好。

**应该**：至少 2 人搭档（一个懂业务 + 一个懂工程）。

---

## 三、失败的根因

### 根因 1：把 AI Agent 当"银弹"

我以为 Agent 能"自动做所有事"，**没理解 Agent 需要工程化**。

**真相**：Agent 是工具，需要**契约、门禁、可观测、迭代**。

### 根因 2：缺乏工程化思维

我是产品经理出身，工程化思维弱。**重视功能、轻视稳定性**。

**真相**：Agent 项目 80% 是工程，20% 是 AI。

### 根因 3：没做 MVP 验证

我直接做了一个"完整"的项目，没先验证最小可行性。

**真相**：**先跑通最小场景，再扩展**。

---

## 四、失败后的反思

### 如果让我重来

1. **选更简单的场景**：FAQ 自动化、会议纪要提取。
2. **从单 Agent 起步**：不要一上来就多 Agent。
3. **HITL 优先**：高自动化 + 关键节点人工把关。
4. **可观测性先行**：trace + log + metric 必须有。
5. **成本预算**：先想清楚"每月花多少钱可以接受"。
6. **收集反馈**：用户反馈 + 失败案例 + 自动标注。
7. **持续迭代**：每周小迭代，不追求"一次完美"。

### 我学到的核心教训

- **Agent 项目的成功 = 持续迭代能力**，不是"一次交付"。
- **demo 成功 ≠ 生产成功**，真实场景复杂度是 demo 的 10 倍。
- **HITL 是过渡方案**，不是"承认失败"。
- **可观测性是 AI 项目的氧气**，没有它你活不下去。
- **不要追求全自动**，高自动化 + 关键 HITL 是正确的。

---

## 五、我的"失败清单"（给别人参考）

### 项目选型失败

- ❌ 选了"项目进度跟踪"（场景太复杂、ROI 不清晰）。
- ✅ 应该选"FAQ 自动化"（场景简单、ROI 明确）。

### 架构设计失败

- ❌ 只有 prompt，没有 RAG、Tool-use、Memory。
- ✅ 应该 RAG + Tool-use + Memory + 可观测。

### 工程化失败

- ❌ 没有质量门禁、可观测性、成本控制。
- ✅ 应该从第一天起就工程化。

### 推广失败

- ❌ 一个人做所有事。
- ✅ 应该 2 人搭档（业务 + 工程）。

### 心态失败

- ❌ 追求"一次完美"。
- ✅ 应该"持续迭代、快速反馈"。

---

## 六、本章关键 takeaway

- 我的第一个 Agent 项目**上线 2 个月后下线**。
- 8 个错误：把 Agent 当银弹、没有门禁、没有可观测、追求全自动、没收集反馈、成本失控、选错场景、单兵作战。
- 根因：缺乏工程化思维、没做 MVP 验证、把 AI Agent 当银弹。
- **Agent 项目的成功 = 持续迭代能力**，不是一次交付。
- **失败是最好的老师**，但希望你能从我的失败中学到东西。
