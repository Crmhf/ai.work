# 01 - AI Agent 常见误区 FAQ

> 工作中最常被问到的 30 个 AI Agent 误区，每个问题给出**简明答案 + 详细解释 + 相关文档**。

---

## 误区 1：Agent = 更聪明的 ChatGPT

**错**。Agent 是"能自主调用工具 + 记忆 + 规划的 AI 系统"，不只是"更聪明的对话"。

详见：[../../00-articles/02-我对Agent的认知演化.md](../../00-articles/02-我对Agent的认知演化.md)

---

## 误区 2：Agent 一定能取代人

**错**。Agent 在标准化任务上能取代人，在创造性、情感、伦理决策上**短期内不能**取代人。

详见：[../../00-articles/10-我对AGI路径的判断.md](../../00-articles/10-我对AGI路径的判断.md)

---

## 误区 3：Prompt 调优是玄学

**错**。Prompt 调优是**工程任务**，有方法、有评估、有 A/B 测试。

详见：[../40-tech-best-practices/02-Prompt工程最佳实践.md](../40-tech-best-practices/02-Prompt工程最佳实践.md)

---

## 误区 4：Agent 项目和传统软件项目一样

**错**。Agent 项目有 5 大差异：行为不确定、测试方式不同、失败模式不同、调试方式不同、迭代周期更短。

详见：[../40-tech-best-practices/01-AI工程化最佳实践.md](../40-tech-best-practices/01-AI工程化最佳实践.md)

---

## 误区 5：只要 LLM 强，Agent 就强

**错**。Agent 强需要：LLM + 工具 + 记忆 + 规划 + 工程化。**LLM 只是其中一环**。

---

## 误区 6：多 Agent 越多越好

**错**。多 Agent 增加复杂度（通信开销、契约一致性、调试难度）。**能用单体 Agent 解决就别上多 Agent**。

详见：[../../00-articles/04-多Agent协作的边界与陷阱.md](../../00-articles/04-多Agent协作的边界与陷阱.md)

---

## 误区 7：Agent 一定能跑 7×24

**错**。Agent 需要**工程化**（质量门禁、可观测、自愈）才能跑 7×24。**没有工程化的 Agent = demo**。

详见：[../10-tech-multi-agent/08-质量门禁与自愈机制.md](../10-tech-multi-agent/08-质量门禁与自愈机制.md)

---

## 误区 8：RAG 能解决所有幻觉

**错**。RAG 减少幻觉但不能完全消除。**RAG + 答案验证 + 人工复核**才能真正降低幻觉。

---

## 误区 9：模型越贵越好

**错**。GPT-4 不是所有任务都需要。**70% 的任务用 GPT-3.5 足够**，质量影响小但成本降低 80%。

详见：[../40-tech-best-practices/05-成本控制实战.md](../40-tech-best-practices/05-成本控制实战.md)

---

## 误区 10：AI Agent 是黑盒，无法 debug

**错**。AI Agent 通过**trace + log + metric** 可以完整 debug。关键是"愿不愿意做"。

详见：[../40-tech-best-practices/04-可观测性实施清单.md](../40-tech-best-practices/04-可观测性实施清单.md)

---

## 误区 11：Agent 万能，任何任务都能做

**错**。Agent 适合"标准化、有 SOP"的任务。**创造性、情感、伦理任务不适合**。

---

## 误区 12：不需要工程化，AI 自己能搞定

**错**。AI 项目的 80% 是工程（契约、门禁、可观测、监控、错误恢复），20% 是模型能力。

---

## 误区 13：本地部署一定比 API 便宜

**错**。本地部署需要：GPU 成本 + 运维成本 + 模型微调成本。只有**量大且稳定**时才便宜。

---

## 误区 14：Fine-tuning 是必须的

**错**。**90% 的场景 prompt 工程 + RAG 就够了**。Fine-tuning 成本高、迭代慢。

---

## 误区 15：开源模型一定比闭源差

**错**。在某些垂直任务上，开源模型（如 Qwen、DeepSeek）甚至**优于 GPT-4**。关键看场景。

---

## 误区 16：Vector DB 能解决所有记忆问题

**错**。Vector DB 适合**语义检索**，但**不适合时序、关系、规则**。需要 Memory 系统综合设计。

---

## 误区 17：Agent 决策可以完全无人监督

**错**。**高风险操作必须 HITL**。Agent 在授权范围内自主决策，授权外必须人类审批。

详见：[../../30-roadmap-to-agi/06-从工具到同事到自主体.md](../../30-roadmap-to-agi/06-从工具到同事到自主体.md)

---

## 误区 18：AI 项目 MVP = 一个 demo

**错**。AI 项目的 MVP = 真实用户能用的最小产品。**demo 成功 ≠ MVP 成功**。

详见：[../50-case-studies/04-失败案例为什么我的第一个Agent项目失败了.md](../50-case-studies/04-失败案例为什么我的第一个Agent项目失败了.md)

---

## 误区 19：AI 自动写文档 = 一定写得对

**错**。AI 写文档可能幻觉（编造 API、虚构事实）。**AI 文档必须人工 review**。

---

## 误区 20：AI Agent 不需要日志

**错**。**没有日志的 Agent 项目 = 黑盒**。出问题根本不知道发生了什么。

---

## 误区 21：AI 代码一定比人写得好

**错**。AI 在**模式化任务**上比人强（CRUD、测试用例），在**架构设计、性能优化**上不一定。

---

## 误区 22：所有对话都要进 LLM

**错**。**简单任务（如查询）可以用规则或脚本**。LLM 是"重武器"，别滥用。

---

## 误区 23：AI Agent 项目不需要 Code Review

**错**。AI 生成的代码也需要 Code Review。**LLM 不是完美的程序员**。

---

## 误区 24：AI 一定能理解业务

**错**。AI 理解业务需要**领域知识库 + 业务规则**。没有这些，AI 只能"表面理解"。

---

## 误区 25：AGI 还有 5 年

**不可预测**。AGI 的定义不统一，时间表不可靠。**关注"局部 AGI"（垂直场景）更实际**。

详见：[../../30-roadmap-to-agi/05-AGI落地场景推演.md](../../30-roadmap-to-agi/05-AGI落地场景推演.md)

---

## 误区 26：AI Agent 是"一次性产品"

**错**。AI Agent 是"持续迭代产品"。**每周小迭代，月度大迭代**是常态。

---

## 误区 27：AI 项目安全不重要

**错**。AI 项目有**特殊安全风险**（prompt 注入、数据泄露、幻觉）。必须从第一天起就考虑安全。

详见：[../40-tech-best-practices/06-安全与合规清单.md](../40-tech-best-practices/06-安全与合规清单.md)

---

## 误区 28：AI 项目不需要用户反馈

**错**。**用户反馈是 Agent 持续改进的核心数据**。没有反馈 = 盲调优。

详见：[../50-case-studies/03-客服Agent的5个月迭代.md](../50-case-studies/03-客服Agent的5个月迭代.md)

---

## 误区 29：AI Agent 一定比人快

**不一定**。**简单的 LLM 调用比人快**（< 1 秒），**复杂的多 Agent 编排可能比人慢**（数分钟）。

---

## 误区 30：AI 时代不需要学习编程

**错**。**AI 时代更需要懂技术**——你要能评估 AI 的输出、调优 prompt、设计 Agent 架构。

详见：[../../30-roadmap-to-agi/07-我的Agent学习路线.md](../../30-roadmap-to-agi/07-我的Agent学习路线.md)

---

## 本章关键 takeaway

- 30 个误区覆盖**认知、工程、商业、安全、学习**5 个维度。
- **每个误区背后都有实战教训**，不是凭空想象。
- **核心误区**：Agent 不是银弹、工程化比模型更重要、demo ≠ MVP、持续迭代。
- 详见对应的深度文档。
